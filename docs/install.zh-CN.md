# Ubuntu 安装

[English](install.md)

支持 Ubuntu 24.04 LTS amd64，须有 sudo 权限。安装器供给主机依赖、独立 rootless Podman 身份、随包运行时、已校验平台包及配套 DSH 镜像，无需开发用 Node.js、pnpm、GitHub CLI 或本地构建镜像。

## 成员实例

在**系统设置 → 成员实例**中设置每个成员容器的默认 **CPU（核数）**、**内存（MiB）**和**进程数**。填写正数，CPU 可用小数，进程数须为整数；留空表示不限。新安装默认不限。**使用建议额度**会填入主机内存的一半（最多 4 GiB）、CPU 的一半（至少一核）和 2048 个进程，须按负载检查后保存，不会自动应用。

在账户详情的**实例资源额度**中选择**继承默认值**或**自定义额度**。自定义会替换全部三个默认字段，留空的字段也按不限处理。保存只修改目标额度；运行中的实例保留当前额度，直到下次启动或显式应用。应用前对照**目标额度**、**当前额度**和**额度待应用**状态。

在系统设置选择**应用到运行中的实例**，或在账户详情选择**立即应用**，确认受影响实例后执行。支持时在线更新，不支持时会重启实例并中断任务；调低内存可能终止运行中的进程，设置有限内存会禁用 swap。部分失败时须查看各实例结果。容量提示将运行中或启用常驻的成员目标内存去重相加，并单列不限额度的实例；超额只提示，不预留内存，也不阻止启动。

资源设置保存在平台数据库中。不再接受 `DSH_PHALANX_CONTAINER_ARGS_JSON`；请移除该变量，在管理页面设置成员额度。

在**系统设置 → 成员实例**中设置空闲回收秒数，默认 1800，0 表示不回收。部署中的空闲配置只导入一次，之后通过系统设置修改。开发模式同样执行空闲回收与常驻行为；容器资源额度仍只在容器模式生效。

在账户详情勾选**常驻实例**并保存。启用的常驻成员会在平台启动或升级完成后自动启动，自动启动最多并发两个；导航进入排队中的成员工作区会将其提到队首。常驻实例不因空闲被回收，确认意外退出后会重新拉起。自动启动失败会显示失败时间，平台不会持续重试；进入该成员工作区可重新尝试。

禁用账户会停止实例并保留常驻设置，重新启用后恢复自动启动；删除账户会删除该设置。常驻数量不设上限。容量提示将运行中或常驻成员去重计算，内存超额只提示、不阻止启动。**平台重启会中断常驻实例中的任务。**

## 存储布局

`DSH_PHALANX_DATA_ROOT` 保存本机制品、生成的投影与运行期状态。默认数据根为 `/var/lib/dsh-phalanx/data` 时，用户空间位于 `/var/lib/dsh-phalanx/data.durable/users`，内置 PostgreSQL 位于 `/var/lib/dsh-phalanx/data.durable/postgres`。显式外部用户卷和 PostgreSQL 使用配置的位置。默认目录无需独立挂载；只有选择外部卷时才写入 `USER_DATA_ROOT`、`USER_DATA_MOUNT`。

| 层 | 持久内容 | 恢复要求 |
| --- | --- | --- |
| 平台数据库 | 账户、授权、设置、使用记录及加密的集成凭据 | 恢复一致的 PostgreSQL 备份 |
| 平台代码 | 分版本的平台程序、更新器和配套镜像 | 恢复匹配且已校验的发布字节 |
| 用户空间 | 成员文件、原生设置与私有重置备份 | 保留实际用户根及归属 |
| 可重建区 | `data` 下的本机制品、投影、缓存与运行文件 | 保留本机制品输入；投影可重新生成 |
| 本机运维状态 | 主密钥、数据库连接、部署设置及升级和维护回执 | 恢复匹配的受保护组合，主密钥另做离线备份 |

### 安全边界

信封加密防止数据库内容或数据库备份泄露时暴露平台秘密，不防平台主机被攻破，也不对能读取主密钥的部署者保密。同时取得数据库密文和匹配主密钥即可解密。成员自配密钥与文件由成员自行保管。所有备份都应私下保存；生成的投影不得包含平台供应商或集成秘密。

### 主密钥备份

主密钥文件为 `/var/lib/dsh-phalanx/keys/master.key`，数据库连接文件为 `/var/lib/dsh-phalanx/keys/database.json`。将主密钥单独离线备份，与数据库备份分开保存。同时保留受保护的数据库连接文件、部署环境及原权限。已安装的主密钥和连接文件归服务账户所有，权限为 `0600`。只核对已安装密钥的指纹、不输出密钥内容：

```sh
sudo -u dsh-phalanx /opt/dsh-phalanx/current/start master-key-fingerprint --config-file /var/lib/dsh-phalanx/keys/database.json --data-root /var/lib/dsh-phalanx/data
```

丢失主密钥后无法解密已有秘密。秘密重置会清除受保护的平台凭据，要求重新登录和配置凭据，不能替代备份恢复。轮换后重新制作离线备份，并保留恢复操作仍需要的旧密钥与配置组合。

### 数据库切换与密钥轮换

外部 PostgreSQL 须为 14 或更新版本，数据库账户须拥有或有权创建平台的 `dsh_phalanx` schema。使用空 schema 或匹配的本平台数据库，其他产品的对象会被拒绝。`verify-full` 验证服务器证书与主机名，`require` 只加密而不验证证书，`disable` 不加密；TLS 失败不会回退明文。

切换到外部库前，私下准备 `/var/lib/dsh-phalanx/keys/database-target.json`，填写所选连接字段（`host`、`port`、`database`、`username`、`password`、`tls`，需要时填写 `ca`），归 `dsh-phalanx` 所有、权限 `0600`。不要放进数据根，也不要把口令写进命令参数。托管命令使用当前安装配置：

```sh
sudo /opt/dsh-phalanx/current/start database-switch --target external
sudo /opt/dsh-phalanx/current/start maintenance-status
sudo /opt/dsh-phalanx/current/start database-switch --target builtin
sudo /opt/dsh-phalanx/current/start master-key-rotate
sudo /opt/dsh-phalanx/current/start maintenance-status
```

在维护窗口逐次执行，每次完成后再启动下一项。切换会复制、核对平台事实后再选择目标，保留原库；轮换重新包裹数据密钥。两者会中断成员任务，并有独立维护回执。检查结果后，可用 `maintenance-recover` 继续可恢复的中断操作；按恢复指引处理，不手改连接文件或删除维护标记。新部署核验完成前保留源库与恢复文件。

### 一致备份与整机迁移

先停平台并确认成员容器已停止，再制作一致备份。冷备内置数据库时还须停止 PostgreSQL 服务；外部 PostgreSQL 须取得匹配的一致备份。将数据库、主密钥、连接文件、`/etc/dsh-phalanx/environment` 和实际用户根作为同一部署组合保留，维持归属和权限。

还须复制数据根中的本机制品，包括上传技能的文件和 ZIP、插件归档与准备时保留的原包、贡献包。SQL 引用和摘要无法重新生成没有下载源的上传原件。直接复制完整数据根最省事；只有在保留输入足以重建时，才可省略生成的投影、缓存及可重新生成的运行文件。

在目标主机恢复匹配的程序与镜像、数据库、密钥和连接配置、本机制品及用户空间。保留部署标识和卷 marker，不要在已有用户数据上初始化新平台。先恢复外部挂载，保持旧主机停机，再启动服务并核对管理员登录、成员进入、文件与各项能力。不要让两台主机同时连接同一平台数据库。恢复核验完成前保留原始备份。

升级器不备份用户空间。停平台并确认成员容器已停止后，将实际用户根归档到该根之外的私有存储。
Ubuntu 上的默认用户根可用以下示例：

```sh
sudo sh -c 'umask 077; tar --acls --xattrs --numeric-owner -cpf /path/to/private-backup/users.tar -C /var/lib/dsh-phalanx/data.durable/users .'
```

先创建私有备份目标；使用外部用户根时替换为实际配置路径。保留整个用户根，包括存储 marker
及环境重置备份。将归档与上面的匹配部署组合一同保存，核对归档可列出、可按原归属与权限恢复。
升级失败后的自动恢复不能代替这份备份。

## Office 预览字体

用户实例镜像随附 Debian Bookworm 的 Noto CJK（`1:20220127+repack1-1`）、Liberation 2（`2.1.5-1`）、Carlito（`20220224-1`）和 Caladea（`20200211-1`）。这些字体使用 SIL Open Font License 1.1，版权及许可说明保留在镜像内的 `/usr/share/doc/<package>/copyright`。官方 Office 转换器读取系统字体目录，并保留其默认字体替代规则。文档指定的字体缺失时，原生预览仍会显示提示；替代字体可能改变排版。

预览不会改写 Office 原文件。镜像升级后重启实例会创建新的转换器代次，重新打开已有文件时使用新字体，不复用旧转换器缓存的 PDF。不提供字体上传或字体管理页面。电子表格预览保留 DSH 的原生表格渲染器。

## 下载产物

产物卡片和文档预览工具栏提供**下载**操作。浏览器保存路径下当前的原文件，包含无法预览的格式；Office 文件不会被转换后的预览 PDF 替代。中文文件名保持可识别。旧聊天中的引用跟随当前文件，不保存历史快照。

下载要求成员仍处于登录状态且会话有效。文件必须位于该成员的私有 HOME 或会话工作区，并通过原生文件权限检查。文件不存在或不可读时显示局部错误。较大文件分块传输；读取期间文件变更会使浏览器下载失败，请在写入完成后刷新重试。

## HTML 文件交互预览

HTML 和 HTM 文件打开时默认允许脚本交互，不受 **Show coding view** 开关影响。按钮、本地表单事件和 DOM 更新在隔离预览中执行；重新打开或重新读取文件会重置内存中的状态。

文件预览支持自包含文档：脚本不能读取平台页面或其登录凭据。资源加载及 API 请求受内容安全策略限制，但不保证阻止所有网络导航。不保证持久存储、任意外部资源可用或应用代码自身正确。需要服务端的应用应启动 HTTP 服务；打开文件本身不提供应用数据保存或服务托管。

## 私有 HTTP 服务预览

DSH 侧栏不再显示平台的服务预览按钮。既有认证预览路由仍可使用：登录后打开 `<平台地址>/service-preview/`，可查看服务端口、应用路径以及可复制给助手的指引。使用既有执行工具在自己的实例中启动应用。例如使用端口 `4300`，应将静态资源、API 和 WebSocket 的基础路径配置为入口显示的完整前缀 `/preview/<spaceId>/4300/<预览凭据>/`；应用会收到完整前缀。可信浏览器链接为 `<平台地址>/service-preview/<spaceId>/4300/<应用路径>`。前缀错误可能导致页面不存在或资源失效，修正应用配置后重新加载。不支持重定向和 Service Worker。

部署者需配置独立的预览监听端口和浏览器来源。首次安装时，在 `--public-origin http://192.0.2.10:18080` 之外添加 `--preview-port 18081 --preview-origin http://192.0.2.10:18081`。已有安装按[服务管理](#服务管理与恢复)说明，在受保护的环境文件中同时设置 `DSH_PHALANX_PREVIEW_PORT="18081"` 和 `DSH_PHALANX_PREVIEW_ORIGIN="http://192.0.2.10:18081"`，然后重启服务。示例 IP 应替换为实际部署主机。预览监听沿用平台绑定地址，端口不能与平台或私有网关相同；未配置时入口会提示缺失条件。

两处公开来源必须使用相同的主机名或 IP、相同协议及不同端口。纯 IP HTTP 部署不需要域名。HTTPS 部署需为两处来源配置 TLS 终止，证书须受浏览器信任并覆盖主机名/IP；分别转发到对应监听端口，并保留 Host 和 Origin。预览来源也必须为 HTTPS，不支持绕过证书校验或混合内容。网络规则和 TLS 代理由部署者管理；升级维护会同时封闭已配置的预览监听端口。

登录成员可取得随机的受限预览凭据，绑定原登录、空间、端口及运行实例。普通地址栏链接不含此凭据；内部 iframe 链接和应用前缀包含它，属于可转移的预览凭据，请勿分享。它不能访问平台 API。重新登录或替换实例后，应重新获取前缀并调整应用配置。预览应用使用不透明来源，不能使用 localStorage、IndexedDB 或 Cookie；应用数据应保存在服务端。允许端口为 `1024–65535`，排除配置的平台、DSH、私有网关及预览监听端口。目标固定为容器回环服务，链接不能选择宿主、其他成员或内网地址。转发前移除平台 Cookie 和认证头。不透明应用的资源、API 和 WS 请求使用受限预览凭据；应用请求不能签发或续期。预览应用不能读取平台父页面，也不能借用平台的已登录 HTTP/WebSocket 接口。

在可见的可信预览页中真实操作会更新实例活跃时间。后台轮询、闲置页面、空闲 WebSocket 或仅有服务进程存在都不会持续保活。现有 DSH 原生连接和助手任务保留原有活跃规则。退出登录、账户权限失效、实例替换、平台重启或登录过期会撤销预览访问并关闭连接。回收后应先打开工作区，通过已有工具重新启动应用，再打开预览；平台不会恢复任意服务进程，也不提供公开分享或长期托管。

## 公共稳定版本

已完成的稳定版本见 [Releases](https://github.com/dake6767/dsh-phalanx/releases)。运行：

```sh
curl -fsSLo install.sh https://raw.githubusercontent.com/dake6767/dsh-phalanx/main/install.sh && sudo bash install.sh
```

默认选择 GitHub 最新的已完成稳定 Release，排除预发布。指定版本使用 `sudo bash install.sh --version vX.Y.Z`。没有 curl 时可运行 `sudo apt-get update && sudo apt-get install -y curl`，也可通过浏览器下载独立脚本后传到主机。

平台归档和镜像 digest 来自同一 manifest，校验值、tag 提交、镜像身份必须匹配。镜像从 `ghcr.io/dake6767/dsh-phalanx` 按 digest 拉取。安装器不注册自动升级；正式发布时会验证匿名下载和镜像拉取。

安装无需模型密钥。确认浏览器访问地址（或用 `--public-origin` 指定）和全部公网 IPv4，包括 NAT 别名；仅在没有公网 IPv4 时提交空清单。打开安装器输出的 `initializationUrl`，填写管理员用户名和密码后直接进入 `/admin`，邮箱可选。模型尚未配置时，终端和 workspace 仍可用。

在 Model management（`/admin/models`）添加共享模型供应商、密钥和独立模型行，显式保存。Messages Base URL 包含供应商前缀：DeepSeek 为 `https://api.deepseek.com/anthropic`，火山 Coding Plan 为 `https://ark.cn-beijing.volces.com/api/coding`；网关追加 `/v1/messages`。停用或删除默认模型及其供应商前，先选择启用中的替代默认。成员模型目录随配置更新，无需重启平台。

每个模型行都有**支持图片**开关。`deepseek-flash` 等已知识图模型默认打开，
其他模型 ID 默认只支持文本；修改后保存供应商。DSH 在图片上传、`read_image`
和子代理图片输入处都遵守此声明。关闭后，DSH 在模型准入时拒绝图片。
新增模型按同一已知模型表设置默认值；已经保存的声明不变。
开关只声明上游能力，不能让原本不支持图片的模型获得识图能力。


注册后在管理页配置供应商密钥。平台自行生成会话签名密钥，两类密钥均加密存入 PostgreSQL，不再通过部署环境配置。全新安装和正式部署默认使用正式发行渠道。

安装、CLI 升级和管理页升级读取公开发布元数据与资产，不需要 GitHub token 或 API 访问。正式部署读取最新已完成正式版的 `release.json` 指针。候选部署先查同目标版本的正式版，若不存在则读取候选渠道的已发布 run 指针；更高目标版本可升级，同目标版本的另一个候选构建仍视为当前版本。指定版本直接下载对应元数据。安装器在修改主机前交叉核验源码、平台校验值、镜像 digest 和验收记录。元数据缺失或身份不一致时，应选择已完成发布的版本重试，或检查 GitHub 资产前缀。

安装器在 root 所有的回执中记录渠道及来源地址，不写入 PostgreSQL。候选部署转为同号正式版时，执行正常的备份、切换、验证和提交事务，保留账户与成员数据；成功提交后才更新渠道，事务失败时恢复原回执。仅恢复数据库不会改动渠道。管理页不提供渠道管理设置。

## 下载源

在「系统设置 → 下载源」选择「官方」或「中国大陆」，然后按需逐项修改。类别包括 npm、PyPI、Docker Hub/GHCR 镜像、GitHub 资产 和浏览器。首次安装默认为「官方」。受保护的已保存配置供运行依赖准备和后续升级复用；切换预设会重置逐项覆盖。镜像和 GitHub 前缀留空表示直接访问。

```sh
sudo bash install.sh --download-source-preset mainland
```

安装还支持 `--npm-registry`、`--pypi-index`、`--container-mirror`、`--ghcr-mirror`、`--github-proxy-prefix`、`--browser-download-host`。地址不得包含凭据；容器镜像地址必须使用 HTTPS。已弃用的 `--github-api-proxy-prefix` 选项和已保存的 API 覆盖值仍可读取，以兼容旧配置，但不再生效；设置页不再显示 API 字段。命令行选择作用于本次操作；首次选择会保存，已有管理员配置仍作为后续操作的默认值。

「中国大陆」预设使用 npmmirror npm、清华 PyPI、DaoCloud Docker Hub、南京大学 GHCR、ghfast GitHub 资产。浏览器使用 npmmirror，镜像路径缺口通过独立 Chromium 地址覆盖，见[运行依赖准备](skill-execution.zh-CN.md#准备依赖与刷新)。镜像属于外部服务，可能不可用，必要时修改相应类别。下载源改变获取路径，发布身份、校验值和镜像 digest 校验仍会执行。

平台的 npm 下载源控制受管插件准备及其 registry 预检。DSH 原生插件管理器保留独立的 registry 选择，包括 npmmirror；修改平台配置不会改写原生选择。

### 出口代理

安装、CLI 和管理页升级、镜像拉取、Git 导入及运行依赖准备均遵循 `HTTPS_PROXY` / `https_proxy` 与 `NO_PROXY` / `no_proxy`。两种大小写同时存在时，小写优先。首次安装先导出变量，再通过 sudo 保留：

```sh
sudo --preserve-env=HTTPS_PROXY,https_proxy,NO_PROXY,no_proxy bash install.sh
```

代理 URL 带凭据时，通过私有终端输入或受保护文件提供，不要写入命令历史、技能 URL 或诊断报告。安装器把配置保存到部署者持有的受保护 systemd 环境文件 `/etc/dsh-phalanx/environment`，供平台服务和更新器共用。后续操作以已保存配置为准，优先于当前 shell 环境。编辑文件后，重启 `dsh-phalanx.service` 和 `dsh-phalanx-updater.service`。将 `HTTPS_PROXY` 设为空可停用已保存代理。`NO_PROXY` 保留逗号分隔的排除项，并始终包含回环主机；私有网关和预览流量保持本地直连。部署者代理凭据不会复制到成员环境或准备日志。

下载源前缀决定访问哪个地址，出口代理决定流量如何到达该地址，两者可以同时配置。受信下载进程也会将 HTTP 目标（包括 Ubuntu 软件源）交给该代理。代理失败会提示检查 `HTTPS_PROXY` / `NO_PROXY`，不打印凭据。Git 还可用 `GIT_SSL_CAINFO` 指定自定义受信 CA。安装器供给 Git，升级准备阶段发现缺少 Git 时会补装。

## 分组与插件

经过审阅的条目与依赖从**技能 → 技能广场**、**插件 → 插件广场**引入，详见[技能广场](skill-execution.zh-CN.md#技能广场)与[插件广场](plugin-access.zh-CN.md#插件广场)。

每个账户只属于一个分组。新建普通账户进入开户默认分组；迁移时，已有普通账户也进入该组。管理员属于受保护的管理员分组，插件、技能、MCP 与专家都和普通分组一样需要显式配置；库的查看和管理权限来自账户管理员身份，不受这些配置影响。任命或撤销管理员时，同一次操作会调整其所属分组。在「分组管理」中可更改开户默认分组；有成员的分组及开户默认分组不能删除。在「账户管理」中调整成员归属、按分组筛选。

在「插件库」中填写 npm 包名和精确版本，或上传私有 `.tgz` 归档。平台在一次性容器中检查包和依赖，再离线验证实际加载。不支持标签、版本范围或 Git 来源。添加插件不会自动向任何分组授权，也不会自动发布。可在插件详情中设置插件上游、平台凭据和接入配置，步骤与边界见[插件与 MCP 接入](plugin-access.zh-CN.md)。

分组详情的「插件」页签分为两份清单：

- **平台管控**：只读加载管理员选用的库版本，成员不能通过插件管理修改其设置、停用或卸载。未配置平台凭据时，部分插件功能可能受限。授权变化在重启后生效；待生效人数及需确认的「重启受影响成员」用于仍在运行旧配置的成员。
- **预装插件**：实例就绪后在后台原生安装一次，副本随后由成员管理，可改设置、停用、自行升级及卸载。移出清单、换组或成员卸载后都不装回；失败等下次启动重试，页签只提示未完成成员数。换组仅补装该成员还没收到过的插件。同一分组的同一插件不能同时出现在两份清单中。

两份清单都不是安装白名单，成员仍可原生安装及使用终端。原生副本为已有自选或专家只读资格让位；预装仍安装一次并记录成功，直到只读资格结束并重启后才恢复原生加载。成员明确停用的 bundle 保持停用。预装原生副本不使用平台凭据。

发布后，成员从 DSH 侧栏的「平台应用」安装插件。普通插件点击「安装」即经私有下载及校验后装入成员原生 profile，设置可保存；平台交付的副本可从应用中心或原生插件页卸载，也可在原生页自行升级。已有独立同名副本显示「已在原生插件页安装」，在原生页管理，应用中心不会覆盖。原生副本不显示来源标签。

配有平台凭据的已发布插件则保存只读自选，卡片显示「平台共享 KEY」；分组管控显示「平台管控，不可卸载」。只有这些只读情形使用平台凭据及条目接入配置。只读自选与原生副本共存时，撤销自选保留原生副本，重启后释放只读优先。页面语言跟随 DSH 语言设置，与平台语言独立。

取消发布会隐藏条目并清除只读自选，保留分组管控；已安装原生副本、设置及交付历史均保留，重启后仍可用。**下架不等于全员回收，需要强制收回请用平台管控。**失去全部平台授权的成员，下一次平台上游调用立即被拒绝；停用账户也会立即阻止后续调用。

候选版本预检期间仍保留当前选用版本。选用候选时，确认框会显示受影响的分组数和成员数；这改变只读加载，不升级成员已安装的原生副本，原生版本由成员自己管理。上游和接入配置保留；新版本缺失的条目 ID 会被标记并跳过，其余条目和环境变量继续应用。移除库中插件会清除授权、发布、自选、上游、凭据及接入配置，成员原生副本保留。系统升级后，服务就绪前会按选定运行时重新检查当前版本和候选，启动时间可能延长。不兼容插件保留授权，暂停平台加载并下架；选用兼容版本后恢复加载及原发布意图，管理员也可取消自动恢复发布。

插件标为不兼容时，应获取支持当前 DSH 运行时的版本，并作为候选重新预检。平台保留原始插件包和授权记录，不改写第三方插件或恢复已移除的运行时服务。成员原生自装副本需在原生插件页处理。

系统升级保留平台数据。重置成员 DSH 环境会清除其原生插件及平台让位条目，并清除成功预装记录；替代实例按当前分组清单重新预装一次。自选原生插件不自动恢复，成员需重新安装。插件库、分组清单、只读自选、上游、凭据和接入配置保留。管理员与成员发起重置的规则一致。备份时将平台插件状态、账户数据库和成员存储一同保存。

## 平台应用中心与 MCP

从 DSH 侧栏打开「平台应用」，页签依次为「插件 | 技能 | 技能包 | MCP 服务」。账户菜单和恢复页也链接到这个入口。独立 `/market` 页面不可用，应将旧书签改为 DSH 侧栏入口；这不影响 DSH 原生插件管理页。

经分组或技能包获得的技能不会重复作为独立自选技能展示。原生插件操作会报告立即生效或需要重启，平台不自动重启；只读插件配置变化需要重启实例。技能和技能包变更对新会话生效，MCP 变更在 agent 下一轮请求时刷新工具，无需重启。单个页签失败时可单独重试，不阻断其他页签。

管理员在「MCP 库」配置服务、准备命令、凭据模板和工具限制，再通过分组管理授权或上架供成员自选。运行位置、测试、鉴权限制及生命周期见 [MCP 服务](plugin-access.zh-CN.md#mcp-服务)。MCP 状态随平台 PostgreSQL 数据库一起备份。切换受支持的 DSH revision 后，平台重新生成成员 MCP 配置，并按新运行时准备命令依赖，完成后命令才可用。

## 技能

在「技能库」上传一个 ZIP（其中可包含多个技能），或填写公开 Git 来源。审阅发现的技能、文件树和渲染后的 `SKILL.md`，选择导入项，并明确确认同名替换。管理员负责审阅包的行为。平台拒绝不安全路径、链接和特殊文件，对常见密钥文件名及内容模式给出警告，不显示命中值；这些检查不能证明代码安全，也不能发现所有密钥。

手动上传和普通 Git 导入的单个技能不得超过 20 MiB，一次多技能导入不得超过 100 MiB；成员贡献的上限保持不变。通过签名广场安装或更新时，整个仓库最多 16384 个文件、展开总量 128 MiB，单技能最多 64 MiB。超限会显示专门的广场条目超限提示。两条路径仍执行路径与链接检查；已有广场来源记录不会使后续普通 Git 导入获得更大上限。来源根目录存在 `SKILL.md` 时只选择该技能；否则先搜索支持的技能容器目录，再在有限深度内递归发现。frontmatter 的 `name` 使用小写字母、数字和单个连字符，独立于 ZIP 文件名及 `_meta.json`；description 必填。运行时保留名称不能导入，内部技能默认隐藏。导入时不安装依赖、不运行脚本；可单独配置[平台代执行](skill-execution.zh-CN.md)。

### 技能包与多技能导入

「技能包」Tab 将已有技能组合为一个包，可填写名称、描述和串联说明。技能包不嵌套，也不复制技能文件。分组授权和市场自选可作用于整包；成员最终拥有直接获得与通过技能包获得的技能并集，托管授权优先。包内至少有一个可用子技能时才显示串联说明技能。

多技能导入可指定串联说明文档；声明 `orchestration.children` 的文档会预选为串联说明。导入前确认建议包名与子技能。识别出的插件清单可提供建议技能包，其余列入「其他技能」。取消预览不改变技能库。

删除包默认保留子技能。勾选连带删除时，先预览哪些子技能可删除：仍被其他包使用或有显式分组授权的子技能会保留；被删除子技能的直接市场自选会清除。从技能库删除子技能也会清理包引用；空包保留在管理端，成员端不可见。环境重置保留技能包自选，删除账户清除该账户的自选。

### Git 来源与检查更新

支持 `owner/repository`、GitHub tree URL，以及公开 HTTPS Git URL，可带子路径和 `#ref`。不支持私有仓库、SSH、本地路径、注册表 API 或内嵌凭据。导入不使用管理员的 Git 凭据、hooks、全局配置或子模块。

详情页记录来源 URL、路径、ref、commit 和内容标识。「检查更新」展示变更、新增、未变及已删除技能，由管理员明确勾选替换和移除。取消后保留当前技能库，不自动或定时更新。ref 可以指向新 commit，而其中内容未变的技能仍显示未变。

Git 遵循[部署者出口代理](#出口代理)配置，自定义受信 CA 可用 `GIT_SSL_CAINFO` 指定。安装器供给 Git，升级准备阶段发现缺少 Git 时会补装。

管理员分组和普通分组初始都没有技能授权，需在「分组管理 → 分组详情 → 技能」中授权。导入本身不会向任何分组授权，也不会发布。管理员可在技能详情中发布，供全体成员在「平台应用 → 技能」中自选安装和卸载。分组授权的技能显示为平台预装，成员不能自行卸载。取消发布会清除成员自选，保留分组授权；重新发布不会恢复之前的自选。移除技能会同时清除授权和自选。

平台技能文件在成员容器中只读。技能变更在 DSH 新会话生效，无需重启实例。替换、撤权、取消发布或移除可能导致正在使用该技能的任务失败，确认框会显示受影响成员数。平台不保留旧版本。同步失败时，管理页面会提示并提供「重试技能同步」，按已保存的配置重新同步。

成员可在 `~/.dsh/skills` 或 `~/.agents/skills` 保留自己的技能。同名时，成员副本优先于平台副本；平台应用检测到同名顶层目录时会显示覆盖提示，平台不会改动或删除成员文件。这与托管插件的平台副本优先规则不同。撤销平台技能不能撤销成员自己的副本。重置 DSH 环境会保留托管、自选及成员自装技能，重置备份也不包含技能目录。停用账户期间停止分发，删除账户时清理其平台技能目录和自选记录。运行时升级后若出现内置技能同名冲突，技能库会保留包内容、显示原因并停止分发。

### 成员自配技能 Key

请在终端中将第三方 Key 写入自己空间的私有文件，权限设为 `0600`，并放在 DSH 配置重置范围之外。不要将真实 Key 粘贴到对话或共享技能包。例如，在 `~/.config/my-skill/secrets.env` 中保存 `EXAMPLE_API_KEY='your-personal-key'`。成员脚本能够读取这个私有文件。

DSH 不会自动把父环境中名称带 `KEY` 的变量传给 bash 工具；只保存 `.env` 或 DSH 凭据也不够。**每次 DSH bash 调用内**都要先加载私有文件，再进入加载技能时返回的资源目录执行脚本：

```sh
set -a
. "$HOME/.config/my-skill/secrets.env"
set +a
cd /path/returned/when/loading/the/skill
python3 scripts/example.py
```

请按技能要求替换变量名、资源路径和参数。管理员启用[平台代执行](skill-execution.zh-CN.md)后，配置的命令可使用平台凭据，成员无需另配个人副本。

## 使用记录

管理员从管理导航进入「使用记录」，或从成员详情的同名链接查看该成员记录。成员的 DSH 界面和平台能力说明不变。

- **工具**：逐次列出插件上游、远程或共享运行 MCP 的 `tools/call`、平台代执行、Search/Fetch 网关调用。可按时间、成员、分组、能力和结果筛选，并查看成员、分组、能力和 UTC 日期汇总。记录保留开始时分组、能力、结果和耗时，以及路径适用的 HTTP 状态、工具错误或退出码；代执行额外保留首参数。其他参数、请求体、stdin、输出和凭据不记录。
- **模型**：按成员和模型汇总共享 Anthropic Messages 模型的输入、输出、缓存读、缓存写 token。今天、近 7 天和自定义范围都按 UTC；自定义边界须为整小时，结束边界不包含。调用归入开始时的小时和分组。标题生成也调用共享模型并计入请求。用量不完整时保留已知计数，单列用量未知请求；缺失计数不等于零。被拒请求单列计数。成员自有模型不统计。
- **自报**：按成员、技能、UTC 日期显示平台技能加载次数，覆盖托管、市场自选和经专家获得的技能；成员同名覆盖不计。平台核对身份和当前持有，但实例仍可多报或少报，平台无法核实这些计数。日期由平台接收时确定，不标注专家或 provider 来源；失败上报直接丢弃，不影响会话。日计数仅供参考，不能用于管控。

插件本地工具和成员容器运行 MCP 不在自报范围；插件上游、远程或共享运行 MCP 保留网关记录。直接出站代理流量、个人凭据及成员自装或自配内容不记录。

在「系统设置 → 使用记录保留期」选择 1–3650 天，默认 180 天；缩短保留期会清理过期数据。小时或日汇总只在整个桶过期后删除。删除账户不会提前删除保留中的记录。使用事实保存在 PostgreSQL 中，随一致的平台数据库备份保存。

MCP 和代执行使用记录直接写入 PostgreSQL，不导入遗留 JSON 或 SQLite 文件。

## 独立用户数据盘

sudo bash install.sh --version vX.Y.Z --user-data-root /mnt/data/dsh-phalanx-users --user-data-mount /mnt/data

`DSH_PHALANX_USER_DATA_MOUNT`。容器模式要求独立盘实际挂载于指定挂载点，
不能用系统盘普通目录或父目录挂载代替。开发模式允许宿主目录，但不提供容器隔离。

Open DSH 链接。每个 HTTP 与 WebSocket 请求都验证当前账户及空间归属。DSH Cookie、
插件资源、RPC 和 manifest 使用相同前缀。HTTPS 由外部代理终止时，将
`--public-origin` 设为完整浏览器访问地址，并向平台转发完整路径和 WebSocket 升级。

## 入口与持久状态

平台支持 English 和简体中文。在管理导航的外观旁，或登录、初始化和实例恢复页面中选择**平台语言**。「跟随浏览器」按浏览器语言显示；明确选择的语言保存在浏览器 cookie 中，退出登录后仍保留。此偏好不属于账户设置，与 DSH 内部语言选择相互独立。安装脚本、CLI 和诊断输出保持英文。

全新安装默认监听 `0.0.0.0:18080`。确认或覆盖建议的局域网/公网 URL：安装器无法可靠发现云主机 NAT 地址，也不开放安全组端口、注册域名或配置证书。支持 HTTP，部署者可配置下文的 [HTTPS 反向代理](#自定义端口上的-https)。首次安装通过 `--listen-address`、`--port` 和 `--public-origin` 选择监听及访问地址。loopback 部署须自行转发端口，并明确提供对应的浏览器 origin。

初始化链接有效期 24 小时，普通服务重启保留，成功开户后消耗并自动登录。链接片段含秘密，只交给首管理员；安装器只在最终输出中显示，不写入安装回执。

链接验证后，先选择「平台数据库」，再创建管理员。保持默认「内置 PostgreSQL」即可完成普通安装；选择「外部 PostgreSQL」时，填写主机、端口、数据库、账户、口令与 TLS 模式。外部服务器须为 PostgreSQL 14 或更新版本；账户必须拥有 `dsh_phalanx`，或有权在所选数据库创建该 schema。使用空 schema 或匹配的本平台数据库，其他产品的对象会被拒绝。「测试连接」依次报告连通性、版本、所有权与 schema 检查，通过后才能继续。

`require` 加密连接，但不验证服务器证书；`verify-full` 同时验证证书与主机名，服务器使用私有 CA 时可上传或粘贴 CA 证书；`disable` 使用未加密连接。TLS 失败不会自动回退到明文。确认后，账户、使用记录及含密钥的集成配置使用所选数据库。本机连接文件和主密钥文件保存在平台数据目录之外，权限为 0600；连接口令由该主密钥加密。恢复部署时须保留匹配的文件。服务重启保留选择。部署标识与持续持有的会话锁阻止另一个运行中的平台共享同库；持锁连接丢失会停止平台，应检查数据库可用性后重启服务。

取回现有链接或重新生成（使旧链接失效）：

```sh
sudo -u dsh-phalanx /opt/dsh-phalanx/current/start bootstrap-link --data-root /var/lib/dsh-phalanx/data --origin http://192.0.2.10:18080
sudo -u dsh-phalanx /opt/dsh-phalanx/current/start bootstrap-link --data-root /var/lib/dsh-phalanx/data --origin http://192.0.2.10:18080 --renew
```

替换为实际浏览器 origin。初始化后两条命令只返回 `/admin`，不能重开首管理员入口。

安装器管理 `/opt/dsh-phalanx/releases` 及 `current` 链接。受保护配置在 `/etc/dsh-phalanx/environment`，平台账户使用所选平台数据库，用户文件默认在 `/var/lib/dsh-phalanx/data.durable/users`。`dsh-phalanx` 服务账户运行平台及 rootless 容器，用户 systemd 单元通过 linger 在重启后启动，无需交互登录。AppArmor 保持启用，兼容 profile 仅作用于 Podman 和 pasta。

安装向导确认浏览器 URL 和入口端口，展示目录，并提供高级网关/存储设置。非交互执行须明确提供 `--public-origin URL --host-public-addresses COMPLETE_LIST`，确实没有公网别名时才传空清单。缺失或无效的必要信息在大型下载前失败。

首次安装失败后重跑向导，或提供修正参数（如 `--gateway-port 41081`）。安装器显示变更字段名，保留秘密和文件，复用校验通过的下载；无需为这类重试手改配置。成功安装后，同版同配置且健康时返回原入口，不重新部署或重启。冲突配置明确失败，已有配置及存储改动须显式停服维护。校验或依赖失败非零退出，激活失败时恢复原版本（若存在）。不要删除数据根来重试。

服务失败时查看安装器报告及日志：

```sh
sudo journalctl _SYSTEMD_USER_UNIT=dsh-phalanx.service _UID="$(id -u dsh-phalanx)" -n 100
```

## 自定义端口上的 HTTPS

在平台前运行独立反向代理。[nginx 配置](../deploy/nginx/https.conf.example)和 [systemd 单元](../deploy/nginx/dsh-phalanx-edge.service.example)使用独立的 `dsh-phalanx-edge` 身份与进程，不影响其他 nginx 服务。明确的 HTTP/1.1 WebSocket 设置支持 NGINX 1.24 及以上。

配置 TLS 前，先用临时监听器确认外部端口可达。平台使用 loopback 监听，并配置含端口的准确 HTTPS origin。选择空闲私有网关端口（默认 3081）：

```sh
sudo bash install.sh --version vX.Y.Z \
  --host-public-addresses 198.51.100.10 \
  --listen-address 127.0.0.1 --port 18080 --gateway-port 41081 \
  --public-origin https://198.51.100.10:18443
```

示例公网地址须替换为主机完整 IPv4 清单。平台及配套镜像来自同一已验证发布。已有受保护配置须显式修改；重复执行安装器不会静默替换部署信息。

创建锁定密码、无登录 shell 的 edge 身份。证书的 Subject Alternative Name 必须覆盖浏览器使用的准确 IP 或域名。私钥保存在仓库外，仅 edge 身份可读。替换模板路径及地址，安装独立配置与单元，通过 `nginx -t` 后启用。单元提供自己的可写运行目录和优雅关闭。

私有测试 CA 的公共证书须导入每位测试者的信任库，并通过部署通道核对指纹；CA 签名私钥保留在部署工作站。证书日期、信任链和地址匹配必须正常验证，浏览器验收保持 `ignoreHTTPSErrors` 关闭。预览结束后移除该测试 CA 信任。公共部署使用正常受信证书并自行安排续期，模板不申请或续期证书。

代理保留含端口的 Host，并转发 Upgrade、Connection 以支持 WSS；关闭响应缓冲以支持流式响应。平台公开 origin 控制相对登录跳转和 Secure Cookie，后端仍为 loopback HTTP。模型网关和容器发布端口也保持 loopback。这里的 18080 仅供本机调试，对外入口为 HTTPS 18443。

通过受信入口验证初始化/登录、账户管理、原生流式响应和真实 WSS 帧；从外部确认后端、网关和实例端口不可达。`tests/https-preview.e2e.ts` 使用私有访问文件，保留部署管理员，只通过管理 API 删除自己创建的测试成员。

停止预览只停用 `dsh-phalanx-edge.service` 及安装器拥有的用户服务，保留配置和数据。退役时只删除本次单元、配置、证书与运行目录。平台按记录的发布和配置重启或恢复，不重启共享 nginx，也不清理其他身份的容器。

参考：[NGINX WebSocket 代理](https://nginx.org/en/docs/http/websocket.html)、[Host 转发](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header)。

## 服务管理与恢复

在 Ubuntu 主机运行以下命令，仅操作安装器的用户服务：

```sh
sudo -u dsh-phalanx env XDG_RUNTIME_DIR=/run/user/$(id -u dsh-phalanx) systemctl --user status dsh-phalanx.service
sudo -u dsh-phalanx env XDG_RUNTIME_DIR=/run/user/$(id -u dsh-phalanx) systemctl --user restart dsh-phalanx.service
sudo -u dsh-phalanx env XDG_RUNTIME_DIR=/run/user/$(id -u dsh-phalanx) systemctl --user stop dsh-phalanx.service
sudo -u dsh-phalanx env XDG_RUNTIME_DIR=/run/user/$(id -u dsh-phalanx) systemctl --user start dsh-phalanx.service
```

stop 不取消开机启动。相同前缀下用 `systemctl --user disable --now` 暂停启动，`enable --now` 恢复。HTTPS edge 单独管理，不为操作平台而重启共享 nginx。

修改已有配置时，用 sudo 编辑 `/etc/dsh-phalanx/environment`，再重启该服务。保留所有权和 0640 权限；配置含共享模型和会话凭据，不能贴入问题报告。一致性备份前停服，保存受保护配置、平台根与用户根及原权限。普通重启重建自有容器，保留原生配置、文件和成员容器主机名。升级时继承已有自有容器的主机名；备份或迁移安装时应保留私有平台数据根。已被残留锁阻塞的应用配置须按应用自身流程恢复；平台不会删除成员文件中的锁。删除账户保留文件；不提供自动数据擦除和灾难恢复。

安装失败时保留配置及数据，修复所报告的网络、依赖或端口问题，用同一已验证版本重试。归档哈希不符须重新获取原始配套资产，不能编辑校验清单。激活失败会自动恢复；主动回退需要此前完成版本、配套镜像/配置及升级前的一致备份。不提供新版 DSH 已写数据的自动反向迁移。

## 配置与支持范围

`bash install.sh --help` 列出首次安装参数：上游 URL/供应商/模型、受保护密钥文件、公网 IPv4 清单、监听及端口、准确公开 origin、私有网关端口。默认模型为 DeepSeek official 的 `deepseek-chat`，后端 `0.0.0.0:18080`，网关 loopback 3081，采用容器模式。`--gateway-port` 只改私有端口，不改绑定地址。HTTPS 后须提供含外部端口的准确 origin。完整公网 IPv4 清单用于拒绝用户代理访问宿主别名；缺少该信息则关闭外部代理访问。

安装器仅支持 Ubuntu 24.04 LTS amd64。[贡献指南](../CONTRIBUTING.md)描述 Mac 开发模式，不承诺容器隔离。Linux 测试验证容器行为，已有服务器不能证明全新安装。项目不提供开放注册、自动升级、多发行版安装或支持 SLA。候选验收和普通 CI 不等于完成公共发布验收。

### 成员登出与恢复

受保护平台插件在 DSH 侧栏账户菜单提供「Log out」「Restart instance」和「更多恢复选项」。登出只清除当前浏览器平台登录，已接受的任务继续执行。重启前须确认中断任务；成功后通过「Return to DSH」回到同一空间，配置、用户插件、聊天和文件保留。

即使 DSH 启动失败，有效成员凭据仍可登录平台并直接进入恢复页。DSH 无法加载时直接访问部署地址的 `/recovery`，仍可登出、重启并查看失败或成功反馈。也可从账户菜单的「更多恢复选项」进入同一恢复页。在「重置 DSH 环境」区块确认任务中断、配置与自行安装的插件会被重置后执行；项目、聊天记录和其他个人文件保留。成员每 10 分钟最多发起一次，失败尝试及平台重启后仍计算冷却时间；管理员不受限。如需找回旧配置，请联系管理员。平台始终使用当前登录身份决定目标。受保护的平台插件及管控或共享凭据只读插件不能通过普通插件管理停用或卸载，成员原生副本仍可管理；成员仍能使用终端和安装自己的插件。此保护不承诺任意用户代码无法干扰本人 DSH。

### 管理员重置 DSH 环境

在成员管理页为已启用成员选择「Reset DSH environment」，确认中断运行任务后执行。即使成员无法打开 DSH，管理员仍可操作。平台先停止该成员实例，完成私有备份，再重置 web profile（含自装插件）、home patch/环境变量及尚未导入的旧 Settings，最后启动替代实例。空间 URL、项目、聊天和其他个人文件保留；尚无实例的成员也可通过该操作启动。

备份失败保留原配置；重置或启动失败会报告已完成备份及恢复信息，不伪报成功。备份位于用户空间卷 `<userDataRoot>/_environment-backups/<spaceId>/<backupId>`，成员容器不挂载，可能包含私有配置和凭据。结果指向给部署者的 `README.txt` 及记录原有/原先不存在载体的 manifest。manifest 中的 home 以用户根为相对路径；换卷后按当前配置的用户根解析恢复指引。人工恢复须先停平台服务并核实目标容器已移除，将当前载体另存，再只恢复清单所列原配置，不能跟随符号链接。只停平台服务可能留下容器；恢复旧备份也会恢复原故障。新备份完整写入后，每个成员保留最近 3 份完整备份，管理员与成员发起合计。只清理该平台空间内已验证的备份，未知、链接和未完成目录保持原状；删除失败只记录日志，不阻止本次重置。成员详情显示最近一次重置的发起时间与发起人。

## 用户数据改盘


这是 Ubuntu 容器部署的显式停服操作。先自行准备并挂载新盘、配置开机持久挂载，工具不格式化磁盘。先在挂载点下创建归服务账户所有、模式0700的私有父目录，再在其中创建同权限的空目标目录（工具在目标旁暂存副本），不能选择挂载点本身，不能与平台根或源目录重叠，空间须容纳完整副本。源数据始终保留。

1. 按上文命令停止用户服务。编辑前私下备份 `/etc/dsh-phalanx/environment` 和平台状态。
   离线操作期间须保持 PostgreSQL 可连接。停止平台也会停止内置数据库；使用内置库时，先只启动数据库服务：

   ```sh
   sudo -u dsh-phalanx env XDG_RUNTIME_DIR=/run/user/$(id -u dsh-phalanx) \
     systemctl --user start dsh-phalanx-postgres.service
   ```

   使用外部 PostgreSQL 时，保持现有数据库服务运行。
2. 使用原受保护环境，以服务身份运行安装产物的工具。工具取得平台维护锁、移除自有容器、复制且不跟随链接，核验文件内容、类型、权限及链接文本，核验通过后才发布新绑定：

   ```sh
   sudo -u dsh-phalanx env XDG_RUNTIME_DIR=/run/user/$(id -u dsh-phalanx) sh -c '
     set -a
     . /etc/dsh-phalanx/environment
     set +a
     exec /opt/dsh-phalanx/current/start migrate-user-storage \
       --target-root /mnt/new-data/dsh-phalanx/users --mount /mnt/new-data
   '
   ```

3. 成功后，仅将受保护配置的 `DSH_PHALANX_USER_DATA_ROOT`、`DSH_PHALANX_USER_DATA_MOUNT` 改为工具报告的目标和挂载点；保留所有凭据、平台根和原所有权。启动服务，核对已有空间的项目、聊天、个人文件和模型入口；主机重启后再次核对。

私有 JSON 回执和恢复 `README.txt` 位于受保护数据库连接配置同目录的 `storage-migrations/`，不放在平台数据根中；记录源、目标以及原 SQL 绑定和 revision。复制或核验失败不切换绑定；停服、保持原配置并重跑相同命令。绑定发布后尚未改配置时启动失败闭合，不生成空白替代环境。目标已发布经核验的 marker 后，重跑只继续 SQL 发布，保留目标后来新增的文件；已完成的重跑仅核对卷，不再复制。链接父目录、特殊文件、错误所有权、缺盘和不可写根会被拒绝，须显式修复。

回退先停平台，另存并对账切换后写入目标的文件。重跑以上命令，增加 `--rollback`，并保持**原来的 `--target-root` 和 `--mount` 参数**。工具只清理自有载体，校验保留源后以 revision 比较恢复原 SQL 绑定；若此后发生其他换卷则拒绝。两个目录均不重拷、不删除。启动前恢复原受保护环境；回退结果 `targetMount: null` 表示原先使用默认存储，应移除两个显式用户数据设置。保留平台存储身份、两份目录及私有回执。原源盘为外置盘时恢复其挂载，重启核对原文件后再开放入口。遵循回执恢复指引，不为绕过缺盘错误删除绑定事实。

## 安装输出与诊断


默认输出英文完成摘要，重定向时也一样。阶段、耗时、真实下载字节、镜像/依赖日志和等待
提示写 stderr，不估计总体百分比。自动化必须显式传 `--output json`，stdout 仅有一份最终
结果；失败有结构化结果及非零退出。`--verbose` 提供脱敏命令与产物身份。

每次运行在 `/var/log/dsh-phalanx/` 保存脱敏阶段 JSONL，目录0700、文件0600。失败显示日志
位置、服务状态、可用的服务日志片段和可复制诊断命令。初始化链接仅出现在部署者最终
结果，凭据、密钥、授权载体不进入诊断输出或持久日志。

本机就绪不等于公网可达，请检查入口端口、防火墙/安全组及已有反代路由。

## 可恢复的系统升级

版本可以声明需要全新安装。此时检查更新会拒绝原地升级，不提供下载或应用操作。先备份原部署和主密钥文件，再另行准备全新安装；在确认不再需要旧数据前保留原部署。当前安装器会在查询不支持的旧数据库之前拒绝升级。已安装的旧版页面可能只显示通用不兼容原因，请按发布说明中的安装指引操作。

兼容的原地升级会先停止旧平台及自有实例，再导出全部已登记 PostgreSQL schema，并备份
密钥、连接配置、部署配置和数据库服务单元。导出工具与所选服务器主版本相同，在停机前准备完成。
迁移或验证失败时，先一起恢复这些内容，再启动旧版本；无关数据库 schema 不在恢复范围内。
用户空间文件不进升级备份，须按上文方法另做一致备份。旧工作全部排空后，验证阶段只读
检查用户存储，提交前不启动成员或常驻实例。可重建制品与投影树原地沿用，维护期间不回收；
恢复会先核对记录的目录仍然存在，再替换平台数据。升级成功或恢复完成后删除本次临时备份；
恢复失败则保留备份，维护状态保持关闭。

停机期间，成员看到按浏览器语言显示的「系统升级中」页面；页面检查就绪状态，完成后自动刷新。
现有 WebSocket 会话会断开。旧安装版本若没有打包维护页，目标监听器启动前可能显示连接重置。
验证期间成员工作始终关闭，就绪响应本身不会提前放开业务。

系统升级模块按当前状态展示可执行操作，包括先更新到断点版本、候选部署转为同号正式版。
应用前须确认任务会中断、成员文件不在升级备份范围内。执行期间展示阶段和已停机时长，
完成后展示停机总时长及各阶段耗时。已知诊断按平台语言显示；未知错误保留原文及受限的服务器日志路径。

升级执行器会在数据库工具或平台包下载、解压、镜像导入和停服前，检查缓存、平台程序、
rootless 镜像层及下载暂存、平台数据和备份各自所在的实际文件系统。
同盘位置共用一份可用空间，所需空间保守累计新增写入；已存在的镜像不重复预留镜像层。
目标镜像不同，仅扣除与已验证当前镜像相同的连续层前缀；离线导入仍预留整包暂存空间。
容量信息缺失或空间不足时，准备过程失败，当前服务保持运行。升级页面和 JSON 操作结果
展示所需、可用、缺少的字节数，以及包含数据库导出估算的备份容量。应用升级前还会再次检查；
检查之后的其他磁盘写入仍可能改变可用空间。

首次下载前、升级验证成功并重新开放服务后，更新器会回收安装回执与镜像身份能证明归属的资源。
保留当前版本和最近一个成功使用的旧版本、已准备目标及未完成恢复所需资源；保护所有运行或停止
容器的引用与运行进程所引用的程序。经验证的历史升级备份会删除；当前操作仍受保护，直到本次
升级成功或恢复完成后释放其备份。未知归属资源、用户数据和恢复执行器保持不动。
清理后重新测量容量，不会为凑足空间而突破保留策略。

系统升级页展示实际观测到的释放量和各资源的保留原因，不将共享层或多个镜像名称重复计算。
升级成功与清理失败分别记录；**重试清理**只重试资源回收，不再次升级、停服或还原旧数据。
服务端也可运行 `sudo bash install.sh --upgrade cleanup --output json`。
中断的清理可从持久化操作继续。保留旧制品是应急储备，不代表支持在新数据写入后任意降级。

如果已安装的执行器不支持所选发布协议、验收检查项或该版本要求的恢复能力，先按安装说明重新下载当前安装器。
不要复用旧脚本；它可能在下载新版执行器前就拒绝新的契约。然后执行
`sudo bash install.sh --upgrade bootstrap --version latest --output json`。
该命令验证发布身份，仅从对应发布提交下载有校验和约束的小型执行器模块，
重启升级执行器，平台继续运行。完成后返回系统升级页面。
已有准备完成或中断的升级操作必须先完成或恢复。使用当前 CLI 安装器直接准备升级，
也会执行容量检查。

部分旧安装在首次受支持的原地升级前，需要执行一次上述 bootstrap。
具体过渡步骤见目标[发布说明](https://github.com/dake6767/dsh-phalanx/releases)；后续只有执行器不满足目标声明的最低读者版本
或所需能力时才需要再次执行。



早于当前版本的安装，请先阅读目标版本 release notes。升级保留现有端口和存储绑定。
应用更新会立即重启服务、打断所有运行任务，并可能丢失未保存内容。交互模式会要求确认；
无终端模式必须显式传入 `--yes`。

```sh
sudo bash install.sh --version vX.Y.Z --yes
sudo bash install.sh --upgrade prepare --version latest --output json
sudo bash install.sh --upgrade apply --operation <prepared-operation-uuid> --yes
sudo bash install.sh --upgrade status --output json
sudo bash install.sh --upgrade recover --output json
```

准备阶段在旧服务运行时下载并验证固定的兼容组合。应用操作始终使用已准备的目标，
不受 latest 后续变化影响。升级失败后，即使旧服务已恢复且验证成功，命令仍以非零状态退出。
恢复失败会保持维护隔离并显示服务器应急指引。保留受保护的操作日志和已验证备份，
查看诊断日志后重试恢复；不要手动删除维护标记或修改 `current` 来绕过失败事务。

发布声明给出兼容 schema 区间、升级下限、断点和最低执行器读者版本。
满足最低读者的执行器容忍未知字段、更高协议号及新增渠道属性，仍校验已知兼容要求与制品完整性；
不满足时，须先用上述已验证安装器更新执行器。不支持的来源 schema 或原生环境改造在切换前被拒绝。
版本列表会指出须先更新到的断点，不直接应用不兼容的最新版。候选部署可通过正常升级事务转为同号正式版，
提交后才更新渠道。不支持任意历史降级。
设计见[兼容性与备份决策](architecture.md#system-update-transaction)。

协议版本会安装独立的 root 服务 `dsh-phalanx-updater.service`。控制 socket
仅供本机受管服务身份使用，Web 平台仍以 `dsh-phalanx` 用户运行。已提交更新
不会因浏览器断开或 Web 服务停止而取消，可用上述 status 命令查询同一操作。
执行器无法启动时，使用已验证独立安装器的 recover 命令，并检查
`sudo journalctl -u dsh-phalanx-updater.service --no-pager`。修复已验证发布包时，
保留 root 所有的操作日志与执行器版本目录；恢复流程验证健康前保持维护入口关闭。

管理员从 **System settings**（`/admin/settings`）进入升级功能。**Check for updates**
手动查询固定项目发布来源，仅选正式版本；检查失败显示更新情况未知并标明检查时间。
**Download update** 在旧服务运行期间校验平台、镜像和执行器。**Apply update**
明确提示服务重启、全部运行任务中断和未保存内容风险；Cancel 保留已准备更新和原有任务。
确认后立即执行，即使仍有任务运行。

断线时保留操作 ID。刷新、关闭页面或 Web 服务停机不会取消已提交操作，页面会查询同一
操作，显示安装版本、验证后的真实运行版本、有限脱敏进度，并区分升级成功与恢复旧版。
普通成员没有更新和诊断 API 权限。Web 或 root 执行器不可用时，使用上述独立安装器应急命令。

## 安装进度


交互终端保留已完成阶段，当前动作原位刷新；重定向或能力有限的终端使用简洁追加
记录和低频等待提示，不输出光标控制序列。下载总量已知时显示真实数量与百分比，
未知时显示已有数量或耗时；阶段与总耗时分别标明。

详细脱敏诊断仍保存到输出指出的受限日志路径，`--verbose` 显示底层输出。
`--output json` 的 stdout 保持一份最终 JSON，过程写入 stderr。失败显示原因、
下一步及诊断路径。这些展示变化不改变确认、升级恢复边界或所选发布身份。

## 成员技能贡献

成员可以让自己的 agent 把技能目录提交到平台。平台工具展示用途、文件列表和已排除的
本地凭据文件；成员本人选择**提交**后才会上传。取消不会改变平台内容。
子 agent 必须回到主会话完成确认。

从**平台应用中心 → 技能 → 我的贡献**查看状态，并在待处理时撤回。
每位成员最多有 20 份待处理贡献；同名重交会替换本人原先的待处理副本。

管理员从**技能库 → 成员贡献**审阅贡献者、用途、文件与渲染后的说明。
**采纳贡献**生成独立的技能库副本，不会自动发布或授权普通分组。
**不采纳**时可以填写成员可见的原因。已撤回和未采纳记录保留 30 天后清理；
删除账户会清除其待处理贡献，已采纳的技能库副本保留。

技能声明包含 `purpose`、可选的 `requiredCommands` 和 `execution`：

```json
{
  "purpose": "搜索团队文档",
  "requiredCommands": [{ "name": "search-cli", "purpose": "搜索文档", "installation": "将已审查的固定版本 CLI 安装到 $RD_OUT/bin。" }],
  "execution": {
    "commands": [{ "command": "search-cli", "blocked": ["configure"] }],
    "variables": [{ "name": "SEARCH_KEY", "purpose": "请求认证", "application": "在服务商控制台申请 Key" }]
  }
}
```

声明只写名称和说明，不写凭据值。工具在上传前检测凭据，平台收到后再次检测归档和声明。
私钥和高置信度凭据赋值会被拒收；结果返回编码、级别、文件和修改建议，隐藏命中值。
遇到警告，agent 应先询问成员是否修改；原样提交需要明确选择 `retainWarnings`，再由成员确认。
原始归档保持不可变，贡献与技能库的预览会隐藏检测到的值。

管理员按「审阅 → 配置 → 分发」采纳。配置阶段将所需命令匹配到就绪运行依赖；缺失命令可在
此处审查并准备依赖后再采纳。代执行命令和机密变量名称另行预填，已保存的机密变量留空即可保留。
发布和普通分组授权均可不选，沿用现有影响检查。旧声明中的 `execution.prepare` 被忽略。
详见[所需命令配置](skill-execution.zh-CN.md#贡献技能与所需命令)。

新贡献技能采纳后，贡献者成为维护人，只有其当前账户可提交同名更新。
已有技能若没有维护人，默认保持为空，采纳时可明确设为贡献者。技能以
内容差异而非版本号区分；审阅展示文件的新增、修改、删除与声明差异。
已有代执行命令、变量值及只写凭据保留，只预填新增项，移除项标出供管理员
决定。更新会展示所需命令的变化；已有迁移准备若依赖发生变化的技能内容，仍需管理员确认。
可在**技能详情 → 版本管理**转交或清空维护人。管理员导入替换保留维护人，
版本记录标为管理员来源。平台应用中心显示贡献署名，采纳时可选匿名。

# 管理员指南

[English](admin-guide.md) · [安装](install.zh-CN.md) · [运维指南](operations.zh-CN.md) · [成员指南](member-guide.zh-CN.md)

在管理后台管理账户、分组和平台能力。部署、升级与备份见[运维指南](operations.zh-CN.md)。

## 共享模型

在「模型管理」（`/admin/models`）选择供应商协议，添加密钥和独立模型行，显式保存。Base URL 保留该协议要求的前缀：Anthropic Messages 下 DeepSeek 为 `https://api.deepseek.com/anthropic`，火山 Coding Plan 为 `https://ark.cn-beijing.volces.com/api/coding`，网关追加 `/v1/messages`；OpenAI Chat Completions 或 OpenAI Responses 下按供应商要求保留版本前缀（如 `https://api.deepseek.com/v1`），网关追加 `/chat/completions` 或 `/responses`。停用或删除默认模型及其供应商前，先选择启用中的替代默认。成员模型目录随配置更新，无需重启平台。

每个模型行都有**支持图片**开关。`deepseek-flash` 等已知识图模型默认打开，
其他模型 ID 默认只支持文本；修改后保存供应商。DSH 在图片上传、`read_image`
和子代理图片输入处都遵守此声明。关闭后，DSH 在模型准入时拒绝图片。
新增模型按同一已知模型表设置默认值；已经保存的声明不变。
开关只声明上游能力，不能让原本不支持图片的模型获得识图能力。

每个模型的**支持推理级别**默认关闭，包括已有模型。仅在上游支持选择推理强度时打开。
此声明让 DSH 在会话模型选择器中提供关闭、低、中、高四档；关闭此开关后不显示推理等级控件，
并不代表开启或关闭模型本身的推理能力。默认档位由成员或供应商决定，平台原样透传推理字段，
不设置默认等级。

## 平台联网搜索与语音输入

打开「系统设置 → DSH 功能」。在「平台联网搜索」中启用搜索，填写专用的「DeepSeek Search API Key」并保存。共享模型供应商密钥不会配置搜索。已保存搜索密钥时，留空可保留原值。关闭搜索会保留密钥，「清除搜索密钥」会删除它并关闭搜索。成员下次启动实例时取得此设置。平台提供联网搜索工具，内置网页抓取工具在平台内不可用。

在「平台语音输入」中选择「标准（INT8）」或「高精度（FP32）」并启用语音输入。FP32 下载更大，每个成员实例也需要更多内存。等待「语音输入已开启」。下载、校验或保存失败时，查看页面给出的原因，再选择「重试准备」。切换精度时，正在使用的模型会在新模型准备期间继续可用。成员下次启动实例时取得此设置。远程使用麦克风时，通过 HTTPS 打开平台并授予浏览器麦克风权限。本机也可通过 localhost 使用麦克风。

## 平台凭据与成员凭据

在相应管理设置录入供应商和插件服务密钥。平台凭据加密保存在 PostgreSQL 中。已保存的插件上游密钥通过管理接口只显示是否配置及末四位。其他凭据可能只显示配置状态。数据库与匹配主密钥的关系见[主密钥备份](operations.zh-CN.md#主密钥备份)。

适配后的原生插件收到的是有限作用域的平台服务令牌。平台网关核验令牌的作用域和授权，再将真实上游密钥加入发送给供应商的请求。插件设置中名为 `apiKey` 的字段可能保存平台令牌。成员能在自己的插件设置中读到该令牌。配置和撤权见[插件与 MCP 接入](plugin-access.zh-CN.md)。成员自行填入插件的个人密钥由插件保存，平台不会自动将其加密存入 PostgreSQL。

## 成员实例

在**系统设置 → 成员实例**中设置每个成员容器的默认 **CPU（核数）**、**内存（MiB）**和**进程数**。填写正数，CPU 可用小数，进程数须为整数；留空表示不限。新安装默认不限。**使用建议额度**会填入主机内存的一半（最多 4 GiB）、CPU 的一半（至少一核）和 2048 个进程，须按负载检查后保存，不会自动应用。

在账户详情的**实例资源额度**中选择**继承默认值**或**自定义额度**。自定义会替换全部三个默认字段，留空的字段也按不限处理。保存只修改目标额度；运行中的实例保留当前额度，直到下次启动或显式应用。应用前对照**目标额度**、**当前额度**和**额度待应用**状态。

在系统设置选择**应用到运行中的实例**，或在账户详情选择**立即应用**，确认受影响实例后执行。支持时在线更新，不支持时会重启实例并中断任务；调低内存可能终止运行中的进程，设置有限内存会禁用 swap。部分失败时须查看各实例结果。容量提示将运行中或启用常驻的成员目标内存去重相加，并单列不限额度的实例；超额只提示，不预留内存，也不阻止启动。

资源设置保存在平台数据库中。不再接受 `DSH_PHALANX_CONTAINER_ARGS_JSON`；请移除该变量，在管理页面设置成员额度。

在**系统设置 → 成员实例**中设置空闲回收秒数，默认 1800，0 表示不回收。部署中的空闲配置只导入一次，之后通过系统设置修改。开发模式同样执行空闲回收与常驻行为；容器资源额度仍只在容器模式生效。

在账户详情勾选**常驻实例**并保存。启用的常驻成员会在平台启动或升级完成后自动启动，自动启动最多并发两个；导航进入排队中的成员工作区会将其提到队首。常驻实例不因空闲被回收，确认意外退出后会重新拉起。自动启动失败会显示失败时间，平台不会持续重试；进入该成员工作区可重新尝试。

禁用账户会停止实例并保留常驻设置，重新启用后恢复自动启动；删除账户会删除该设置。常驻数量不设上限。容量提示将运行中或常驻成员去重计算，内存超额只提示、不阻止启动。**平台重启会中断常驻实例中的任务。**

在「账户管理」打开目标账户的「更多操作」，选择「切换到该成员 DSH」，输入目标账户密码。成功后进入目标账户的 DSH，原管理员仍在浏览器的已记住账户列表；错误或取消时仍保留原管理员会话。列表已有十个账户时，请先移除一个已记住账户。

同一菜单可为已停止的成员选择「启动实例」，或为正在运行的成员选择「重启实例」。重启前需确认正在执行的任务会中断，配置、插件和持久文件会保留。账户停用或有实例操作进行中时，这两个动作不可用。若其他管理员刚操作过该实例，请先刷新列表。

## 分组与插件

经过审阅的条目与依赖从**技能 → 技能广场**、**插件 → 插件广场**引入，详见[技能广场](skill-execution.zh-CN.md#技能广场)与[插件广场](plugin-access.zh-CN.md#插件广场)。

每个账户只属于一个分组。新建普通账户进入开户默认分组；迁移时，已有普通账户也进入该组。管理员属于受保护的管理员分组，插件、技能和 MCP 都和普通分组一样需要显式配置；库的查看和管理权限来自账户管理员身份，不受这些配置影响。任命或撤销管理员时，同一次操作会调整其所属分组。在「分组管理」中可更改开户默认分组；有成员的分组及开户默认分组不能删除。在「账户管理」中调整成员归属、按分组筛选。

在「插件库 → 添加插件」中输入包名、`package@1.2.3` 或 `package@latest`，也支持 `@scope/package` 等带 scope 的包名。省略版本时使用 `latest`。预检会解析为精确版本，并显示真实包名、来源与已检查内容；点击「确认入库」后才加入插件库，之后 `latest` 改变不会改变已确认版本。不支持版本范围或其他标签。也可以通过单独的上传入口添加私有 `.tgz` 归档。平台在一次性容器中检查包和依赖，再离线验证实际加载。添加插件不会自动向任何分组授权，也不会自动发布。可在插件详情中设置插件上游、平台凭据和接入配置，步骤与边界见[插件与 MCP 接入](plugin-access.zh-CN.md)。

如需从公开 GitHub 仓库添加插件，输入 `github:owner/repo` 或 `https://github.com/owner/repo`。预检会把默认分支固定到最新提交，下载该提交的源码，并在断网容器中打包，不执行任何仓库脚本（包括 `prepare`、`prepack`）。打包结果随后与上传包走相同的检查。预检结果显示仓库 `package.json` 中的真实包名、版本和固定的提交；插件库中版本显示为 `x.y.z (abc1234)`。平台不构建插件，仓库必须包含 `main`、`exports` 与 `dsh.bundle` 声明的构建产物；缺少时预检提示需要构建，请改用 npm 包或上传 tgz。依赖必须来自 npm registry（含 `npm:` 别名），Git、URL 与路径依赖会被拒绝。不支持克隆式 Git 地址（`git+…`、`ssh:`、`git@`、`.git` 归档）、指定分支/标签/提交以及其他 Git 主机。

插件库会记录每个插件的来源。一个包名只对应一个来源：npm、上传或某一个 GitHub 仓库；从其他来源添加或替换同名插件会被拒绝，如需更换来源，请先从插件库移除，再从另一来源添加。可在插件详情中按需「检查更新」：npm 插件比较库内版本与 `latest`，GitHub 插件比较记录的提交与默认分支最新提交；即使包版本号未变，新提交也会提示。平台不会自行检查或更新。点击「预检更新」时，npm 解析新的精确版本，GitHub 按同一 GitHub 预检流程打包新提交，作为替换候选预检；选择该候选前当前版本保持不变。上传的插件通过上传替换包更新。

分组详情的「插件」页签分为两份清单：

- **平台管控**：只读加载管理员选用的库版本，成员不能通过插件管理修改其设置、停用或卸载。未配置平台凭据时，部分插件功能可能受限。授权变化在重启后生效；待生效人数及需确认的「重启受影响成员」用于仍在运行旧配置的成员。
- **预装插件**：实例就绪后在后台原生安装一次，副本随后由成员管理，可改设置、停用、自行升级及卸载。移出清单、换组或成员卸载后都不装回；失败等下次启动重试，页签只提示未完成成员数。换组仅补装该成员还没收到过的插件。同一分组的同一插件不能同时出现在两份清单中。

成员可按分组功能设置使用原生安装和终端。原生副本会让位于同名的只读自选；预装仍记录一次成功，结束只读资格并重启后恢复原生加载。成员明确停用的 bundle 保持停用。受支持的条目可将有限作用域的平台服务设置交给符合条件的原生副本，真实上游密钥留在平台。

发布后，成员可在 DSH 侧栏的「平台应用中心」选择插件。普通插件安装为成员自行管理的原生副本。共享凭据自选以只读方式加载；声明了受支持原生服务绑定的条目可将服务设置交给原生副本。独立安装的同名插件继续在原生插件页管理。参见[成员指南](member-guide.zh-CN.md#进入-dsh-与使用平台应用中心)和[原生服务设置](plugin-access.zh-CN.md#原生插件的平台服务设置)。

取消发布会隐藏条目并清除只读自选，保留分组管控；已安装原生副本、设置及交付历史均保留，重启后仍可用。**下架不等于全员回收，需要强制收回请用平台管控。**失去全部平台授权的成员，下一次平台上游调用立即被拒绝；停用账户也会立即阻止后续调用。

候选版本预检期间仍保留当前选用版本。选用候选时，确认框会显示受影响的分组数和成员数；这改变只读加载，不升级成员已安装的原生副本，原生版本由成员自己管理。上游和接入配置保留；新版本缺失的条目 ID 会被标记并跳过，其余条目和环境变量继续应用。移除库中插件会清除授权、发布、自选、上游、凭据及接入配置，成员原生副本保留。系统升级后，服务就绪前会按选定运行时重新检查当前版本和候选，启动时间可能延长。不兼容插件保留授权，暂停平台加载并下架；选用兼容版本后恢复加载及原发布意图，管理员也可取消自动恢复发布。

插件标为不兼容时，应获取支持当前 DSH 运行时的版本，并作为候选重新预检。平台保留原始插件包和授权记录，不改写第三方插件或恢复已移除的运行时服务。成员原生自装副本需在原生插件页处理。

系统升级保留平台数据。重置成员 DSH 环境会清除其原生插件及平台让位条目，并清除成功预装记录；替代实例按当前分组清单重新预装一次。自选原生插件不自动恢复，成员需重新安装。插件库、分组清单、只读自选、上游、凭据和接入配置保留。管理员与成员发起重置的规则一致。备份时将平台插件状态、账户数据库和成员存储一同保存。

### 按分组配置功能

在「分组管理」打开分组，选择「功能设置」，保存对该分组的修改。

- 「展示平台应用中心」控制 DSH 侧栏入口，成员刷新页面后生效。已获得的库资源继续可用。
- 「手动打开终端」控制终端侧栏和手动终端，Agent 命令与平台代执行仍可用。
- 「自行添加插件」控制从原生插件页安装插件及首次启用官方可选包。平台应用中心可见时，成员仍可从那里安装已发布的插件。
- 「DSH 内置 Agent 预设」控制新会话可用的预设。重启后，使用已停用预设的旧会话需重新开启该预设才能恢复。至少保留一个预设。

手动终端、自行添加插件和内置预设的修改在实例重启后生效。

## 技能、插件和 MCP 广场

从对应的库打开广场页签。技能、插件和 MCP 广场共用同一份签名目录。可在当前广场按名称、说明或条目标识搜索。广场有已分类条目时，可点击搜索框下方的标签按钮，每次选择一个。切换标签时保留搜索词，修改搜索词时保留选中的标签。点击「全部」取消标签限制，结果包含未分类条目。点击「未分类」只显示没有标签的条目。「清除筛选」同时重置搜索和标签。

从 MCP 广场导入或更新时，平台需要先核验目标条目。详情会列出远程服务或共享运行方式，以及需要填写的凭据。目标不可用时可点击「重新加载 MCP 广场」重试。已安装的 MCP 服务继续使用保存的配置、凭据和授权，可在 MCP 库的「MCP 服务」页签维护和测试。更新需要管理员明确确认。

## 平台应用中心与 MCP

管理端的插件、技能、技能包和 MCP 详情首个区块统一为「平台应用中心」，分别显示上架状态与可用性，并提供独立的上架、下架及影响确认。新资源先保存；有未保存修改时先保存或放弃，再操作上下架。广场内容保持只读，上下架由管理员独立决定，更新保留该决定。插件因不兼容暂停时，会说明自动恢复意图，并允许取消恢复。已上架的空包或冲突包会说明成员暂不可用的原因。涉及平台凭据时，确认框说明全体成员可经资源使用凭据。下架保留分组授权，重新上架不恢复已清理自选；普通插件的原生已安装副本保留，共享凭据插件自选在重启后停止加载，技能、技能包和 MCP 清理对应资源的成员自选。

从 DSH 侧栏打开「平台应用」，页签依次为「插件 | 技能 | MCP 服务」。账户菜单和恢复页也链接到这个入口。独立 `/market` 页面不可用，应将旧书签改为 DSH 侧栏入口；这不影响 DSH 原生插件管理页。

「技能」页签将可展开的技能包与独立技能放在一起展示。原生插件操作会报告立即生效或需要重启，平台不自动重启；只读插件配置变化需要重启实例。技能和技能包变更对新会话生效，MCP 变更在 agent 下一轮请求时刷新工具，无需重启。单个页签失败时可单独重试，不阻断其他页签。

管理员在「MCP 库」配置服务、准备命令、凭据模板和工具限制，再通过分组管理授权或上架供成员自选。运行位置、测试、鉴权限制及生命周期见 [MCP 服务](plugin-access.zh-CN.md#mcp-服务)。MCP 状态随平台 PostgreSQL 数据库一起备份。切换受支持的 DSH revision 后，平台重新生成成员 MCP 配置，并按新运行时准备命令依赖，完成后命令才可用。

## 技能

在「技能库」上传一个 ZIP（其中可包含多个技能），或填写公开 Git 来源。审阅发现的技能、文件树和渲染后的 `SKILL.md`，选择导入项，并明确确认同名替换。管理员负责审阅包的行为。平台拒绝不安全路径、链接和特殊文件，对常见密钥文件名及内容模式给出警告，不显示命中值；这些检查不能证明代码安全，也不能发现所有密钥。

手动上传和普通 Git 导入的单个技能不得超过 20 MiB，一次多技能导入不得超过 100 MiB；通过签名广场安装或更新时，整个仓库最多 16384 个文件、展开总量 128 MiB，单技能最多 64 MiB。超限会显示专门的广场条目超限提示。两条路径仍执行路径与链接检查；已有广场来源记录不会使后续普通 Git 导入获得更大上限。来源根目录存在 `SKILL.md` 时只选择该技能；否则先搜索支持的技能容器目录，再在有限深度内递归发现。frontmatter 的 `name` 使用小写字母、数字和单个连字符，独立于 ZIP 文件名及 `_meta.json`；description 必填。运行时保留名称不能导入，内部技能默认隐藏。导入时不安装依赖、不运行脚本；可单独配置[平台代执行](skill-execution.zh-CN.md)。

发现阶段逐个校验技能。`SKILL.md` frontmatter 无效的技能会列入「无法导入」，显示文件路径、出错字段和原因；同一预览里其余合法技能仍可导入，description 含冒号需加引号时会说明。仓库级问题（不安全路径、链接或特殊文件）仍整批拒绝；没有任何合法技能时保留原有的「未找到技能」类错误。

### 技能包与多技能导入

「技能包」Tab 将已有技能组合为一个包，可填写名称、描述和串联说明。技能包不嵌套，也不复制技能文件。分组授权和市场自选可作用于整包；成员最终拥有直接获得与通过技能包获得的技能并集，托管授权优先。包内至少有一个可用子技能时才显示串联说明技能。

新建技能包默认下架。编辑保存保留原上架决定；在详情的「平台应用中心」区块独立上下架。空包可以保持已上架状态，同时标明成员暂不可用，不增加上架前置条件。下架技能包清理该包自选，保留分组授权与成员的单技能自选。

技能库、分组授权和成员技能选择都以可展开条目展示技能包。包内技能通常只在包中展示；有直接分组授权或成员单独选择的技能仍保留顶层入口。成员看不到任何父包时，原本可见的技能仍保留独立入口，不公开隐藏父包及其其他子技能。展开可见包可以查看子技能，但单独安装与完整详情仍按原有发布和直接授权规则控制。选择或授权整包后，包内全部可用技能仍可使用，已有分组选择保持不变。

多技能导入可指定串联说明文档；声明 `orchestration.children` 的文档会预选为串联说明。导入前确认建议包名与子技能。识别出的插件清单可提供建议技能包，其余列入「其他技能」。取消预览不改变技能库。

删除包默认保留子技能。勾选连带删除时，先预览哪些子技能可删除：仍被其他包使用或有显式分组授权的子技能会保留；被删除子技能的直接市场自选会清除。从技能库删除子技能也会清理包引用；空包保留在管理端，成员端不可见。环境重置保留技能包自选，删除账户清除该账户的自选。

### Git 来源与检查更新

支持 `owner/repository`、GitHub tree URL，以及公开 HTTPS Git URL，可带子路径和 `#ref`。不支持私有仓库、SSH、本地路径、注册表 API 或内嵌凭据。导入不使用管理员的 Git 凭据、hooks、全局配置或子模块。

详情页记录来源 URL、路径、ref、commit 和内容标识。「检查更新」展示变更、新增、未变及已删除技能，由管理员明确勾选替换和移除。取消后保留当前技能库，不自动或定时更新。ref 可以指向新 commit，而其中内容未变的技能仍显示未变。

Git 遵循[部署者出口代理](operations.zh-CN.md#出口代理)配置，自定义受信 CA 可用 `GIT_SSL_CAINFO` 指定。安装器供给 Git，升级准备阶段发现缺少 Git 时会补装。

管理员分组和普通分组初始都没有技能授权，需在「分组管理 → 分组详情 → 技能」中授权。导入本身不会向任何分组授权，也不会发布。管理员可在技能详情中发布，供全体成员在「平台应用 → 技能」中自选安装和卸载。分组授权的技能显示为平台预装，成员不能自行卸载。取消发布会清除成员自选，保留分组授权；重新发布不会恢复之前的自选。移除技能会同时清除授权和自选。

平台技能文件在成员容器中只读。技能变更在 DSH 新会话生效，无需重启实例。替换、撤权、取消发布或移除可能导致正在使用该技能的任务失败，确认框会显示受影响成员数。平台不保留旧版本。同步失败时，管理页面会提示并提供「重试技能同步」，按已保存的配置重新同步。

成员可在 `~/.dsh/skills` 或 `~/.agents/skills` 保留自己的技能。同名时，成员副本优先于平台副本；平台应用检测到同名顶层目录时会显示覆盖提示，平台不会改动或删除成员文件。这与托管插件的平台副本优先规则不同。撤销平台技能不能撤销成员自己的副本。重置 DSH 环境会保留托管、自选及成员自装技能，重置备份也不包含技能目录。停用账户期间停止分发，删除账户时清理其平台技能目录和自选记录。运行时升级后若出现内置技能同名冲突，技能库会保留包内容、显示原因并停止分发。

### 管理员重置 DSH 环境

在成员管理页为已启用成员选择「Reset DSH environment」，确认中断运行任务后执行。即使成员无法打开 DSH，管理员仍可操作。平台先停止该成员实例，完成私有备份，再重置 web profile（含自装插件）、home patch/环境变量及尚未导入的旧 Settings，最后启动替代实例。空间 URL、项目、聊天和其他个人文件保留；尚无实例的成员也可通过该操作启动。

容器实例为原生插件提供私有系统凭据服务。普通重启会保留该服务保存的凭据。重置 DSH 环境时，凭据库随 web profile 一起进入私有备份，新实例使用空白凭据库。

备份失败保留原配置；重置或启动失败会报告已完成备份及恢复信息，不伪报成功。备份位于用户空间卷 `<userDataRoot>/_environment-backups/<spaceId>/<backupId>`，成员容器不挂载，可能包含私有配置和凭据。结果指向给部署者的 `README.txt` 及记录原有/原先不存在载体的 manifest。manifest 中的 home 以用户根为相对路径；换卷后按当前配置的用户根解析恢复指引。人工恢复须先停平台服务并核实目标容器已移除，将当前载体另存，再只恢复清单所列原配置，不能跟随符号链接。只停平台服务可能留下容器；恢复旧备份也会恢复原故障。新备份完整写入后，每个成员保留最近 3 份完整备份，管理员与成员发起合计。只清理该平台空间内已验证的备份，未知、链接和未完成目录保持原状；删除失败只记录日志，不阻止本次重置。成员详情显示最近一次重置的发起时间与发起人。

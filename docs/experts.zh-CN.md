# 专家

[English](experts.md) · [安装指南](install.zh-CN.md)

专家将人设、可选的共享模型，以及插件库、技能库、技能包和 MCP 库中的条目组合成一个 DSH 工作模式。每个专家固定包含标准的文件、终端、搜索和子 agent 工具。成员原有的全局能力在专家模式中仍然可用。

## 组建与分发

1. 在对应库中准备需要的条目，配置插件的平台上游、技能代执行凭据和 MCP 服务。真实凭据留在平台侧。
2. 打开**专家库 → 创建专家**，填写名称、简介、图标和人设，选择库内条目；也可选择一个已启用的共享模型，填写两三条示例任务。专家人设会追加到标准说明中。
3. 保存。新建专家不会自动发布，也不会自动授权给普通分组。
4. 在**分组管理 → 详情 → 专家授权**中授权，或在专家库发布，让成员到**平台应用中心 → 专家**召唤。管理员分组自动拥有所有专家。

会修改 DSH 已有核心条目的插件不能加入专家。专家引用库中的当前条目，不复制其内容；库中条目更新后，成员下次重启实例时应用新内容。

**召唤后即可在整个实例中使用专家的全部条目，包括未单独授权给你的条目，并由配置的平台凭据完成上游调用。** 凭据值留在平台侧。发布专家后，所有成员都可以通过召唤获得这些使用权。额外条目显示在专家模式中，但网关按成员鉴权，无法按当前会话区分。专家不会限制成员已有的全局能力。

## 召唤与开始对话

打开**平台应用中心 → 专家**，查看包含的条目，点击**召唤专家**，再通过提示中的链接重启 DSH 实例。分组授权的专家显示为已拥有，成员不能自行解散。

点击**开始对话**，会新建一个使用该专家的会话，并预选其已启用的共享模型。成员仍可通过原生模型选择器改用其他模型。专家指定的共享模型不可用时，新会话使用宿主默认模型，管理界面会显示警示。

也可以从 DSH 原生模式列表选择专家。这个入口沿用宿主的模型规则，不会预选专家模型；需要预选时，请使用平台应用中心的**开始对话**。

成员全局安装的插件、技能和 MCP 服务仍然可用。已在全局提供的条目不会在专家中重复加载。同名原生插件沿用现有的平台插件与自装副本共存规则。

## 修改、修复与移除

修改专家后，成员重启实例才生效。重启前，已经开始的会话保留旧定义；重启后，恢复的旧会话和新会话都使用当前定义，不恢复历史修订。

引用条目被删除、不可用或不兼容时，专家会跳过它，保留其余能力。单个插件或 MCP 服务启动失败也会被隔离，不影响健康条目。管理界面标出不可用条目或受影响实例，成员卡片显示部分能力暂不可用。可以编辑专家移除已保存的失效引用，也可以修复库内条目，再重启实例。共享模型不可用时单独显示警示，新会话按默认模型规则处理。

**解散专家**会立即收回仅由该专家提供的使用权。取消发布、撤销分组授权和删除专家也遵循这一规则。独立的分组授权、市场自选或其他已拥有专家仍可继续提供各自的使用权。已经加载的定义在重启后移除。

失去专家并重启后，原专家会话无法继续，但仍可查看历史。重新召唤同一个专家并重启后，可以用它的当前定义继续旧会话。重置 DSH 环境会保留专家定义和召唤记录。

管理员删除前会看到当前持有的成员和授权分组。确认删除会清理对应授权与召唤记录；影响范围变化时，需要重新查看预览。删除后重新创建的专家具有新的身份，不能恢复属于原专家的会话。

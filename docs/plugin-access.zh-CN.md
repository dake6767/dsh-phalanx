# 插件与 MCP 接入

[English](plugin-access.md)

平台应用是管理员在插件库中预检并提供给成员的插件。普通应用中心安装与分组「预装插件」创建成员自行管理的原生副本；「平台管控」及共享凭据自选只读加载管理员选用的版本。安装与卸载操作见[分组与插件](install.zh-CN.md#分组与插件)。

插件上游保存服务地址、请求头和平台凭据。接入配置把环境变量及按条目 ID 合并的配置提供给成员实例。获授权的只读使用者可以使用平台凭据，但无法从成员空间读出其值。原生副本不使用平台凭据及条目接入配置。平台交付的原生副本仅在成功交付记录与实际库存同时存在时，启动附加普通字面环境变量及已声明依赖的路径，排除凭据及转发模板；配置变更需要重启。

## 配置步骤

1. 在「插件库」添加精确版本或上传 `.tgz`，等待预检通过。
2. 打开插件详情中的「接入配置」，添加插件上游。地址支持 HTTP(S) 和内网地址；名称只在当前插件内使用。
3. 在「平台凭据」填写真实 Key。在请求头中用 `{credential}` 引用，例如 `Authorization: Bearer {credential}` 或 `X-API-Key: {credential}`。固定请求头覆盖成员提交的同名值，可用于锁定租户。
4. 保存测试请求，点击「测试已保存的请求」。它只验证地址、凭据和请求头；仍需配置接入并实际调用插件，才能确认完整链路。
5. 在环境变量或条目配置中，用 `{upstream:name}` 引用转发地址，用 `{access-token}` 引用成员令牌。这里不要填写真实 Key。环境变量对整个实例生效，会覆盖已有的同名启动变量。DSH 优先使用已保存的凭据引用；成员保存的同名引用可能使平台访问失效，删除该引用后恢复使用平台令牌。同一个变量名只能由一个平台应用配置，平台保留变量不可改写。
6. 按界面列出的条目 ID 填写 YAML。对象逐层合并，数组和标量整体替换；不支持 YAML 标签或表达式。保存后，受影响成员重启实例才会加载新配置。
7. 为分组设置平台管控，或发布供成员自选只读访问；预装则交付不带平台凭据的普通原生副本。含平台凭据的应用发布前，需要确认全体成员都将获得使用该凭据的权限。

上游地址、请求头和平台凭据更新后，下一次请求即使用新值，不要求成员重启。删除仍被接入配置引用的上游时，界面会指出引用位置。

已保存的上游凭据和锁定请求头只写不回显。接入环境变量值和整段条目 YAML 也只写，页面与管理接口仅显示是否已配置及末四位。已有值留空表示保留，输入新值表示替换；非空 YAML 整体替换原文档，点击「清除已保存的条目配置」才会清空。删除环境变量或请求头行会移除该项。这些值加密保存在平台数据库中；生成的成员条目文件只含平台环境引用，解析后的值仅传给实例进程。接入配置变更仍需重启实例。

点击「清除已保存的凭据」可单独移除上游 Key，保留地址及接入引用。

已保存的诊断路径及 JSON 请求体也加密且不回显。诊断输入留空保留原请求，输入完整请求可替换，点击「清除已保存的测试请求」才会移除。诊断仍使用原请求，并遮蔽上游响应中回显的受保护值。

## 插件广场

打开**插件 → 插件广场**，引入经过审阅的插件、声明的运行依赖与接入模板。确认前审阅
锁定的包版本、来源、完整性和依赖文件；准备成功后才写入库。随后配置**平台管控**分组
授权，或发布供成员安装；引入广场条目本身不会自动授权。

插件与技能广场共用签名目录和信任设置，见[广场来源与生命周期](skill-execution.zh-CN.md#技能广场)。
平台升级保留已安装条目，不会自动更新它们。点击**更新**审阅包、依赖与接入模板变化；
失败恢复先前可用版本，并保留已存凭据、授权与成员自选。

广场所属项目显示**来自『X』**并保持只读。**脱离『X』**后保留配置与引用，可手动维护；
已脱离项目不再随条目更新，卸载条目时也会保留。共享依赖被其他项目引用时继续保留。
确认卸载前，审阅授权、发布与成员自选的移除预览。

### OnlyOffice

**OnlyOffice** 条目安装 `@dake6767/dsh-onlyoffice`，并为 DOCX、XLSX、PPTX 准备约140 MB
共享 SDK 核心资源。条目自动设置
`DSH_ONLYOFFICE_SHARED_CACHE_DIR={dependency:onlyoffice-sdk}/sdk`，成员只能读取共享树；
缺失资源按需写入各成员自己的 `$DSH_HOME/onlyoffice-sdk`。共享子集不包含完整 SDK。
锁定上游缺少可选的英文拼写字典，可能加载失败；不影响打开与保存文档。

SDK 从固定上游提交下载，逐文件校验 SHA-256，含 AGPL 组件；平台和目录的发布包不携带这些 SDK 字节。
部署前审阅条目来源与许可。成员在 OnlyOffice 文档查看器打开 workspace 文件，保存回原文件。
依赖版本变更在实例重启后生效。

## 运行依赖

先在「运行依赖」创建并准备依赖，再到插件库详情的「运行依赖」页选择它。
「资源文件」类别可承载共享 SDK，无需提供可执行命令或向 PATH 添加目录。
被插件引用的依赖禁止删除，未发布插件的引用也计入保护。

在接入配置的环境变量中，用 `{dependency:名称}` 填入所选依赖的路径，例如
`OFFICE_SDK_ROOT={dependency:office-sdk}`。名称必须在当前插件的声明中；
可拼接相对路径或使用多个占位符。依赖占位符仅用于环境变量。
解除声明前，先移除环境模板中对它的引用。

平台管控、自选、预装和专家插件都会获得其依赖。原生副本启动时注入字面值及依赖路径；
同一行只要含 `{access-token}` 或 `{upstream:名称}`，整行仍被排除。
这些值不写入成员 profile，HOME、PATH、PYTHONPATH 等保留变量仍不可改写。

依赖更新成功后，下一次实例准备使用新版本。运行中的实例保留原路径，并提示重启；
准备失败时继续使用原有可用版本。

## DeepSeek Search/Fetch

DSH 内置网页搜索插件提供 **DeepSeek Search/Fetch API**，默认关闭，成员可在插件设置中自行开启。
**平台已注入，无需填写 API Key。** 上游的 API Key 控件仍然可见，请保持空白；
自行填写会覆盖平台接入并返回 401。

平台使用已启用、Base URL 主机为 `api.deepseek.com` 的 DeepSeek 共享模型供应商凭据，
优先选默认模型所属供应商，其次选第一个符合条件的供应商。只有平台网关向上游附加
真实凭据，凭据不进入成员空间。其他主机上的供应商不提供这份凭据。
没有可用的共享凭据时，插件明确提示需要管理员配置，成员无需自行提供 key。
管理员可在[使用记录](install.zh-CN.md#使用记录)查看 Search/Fetch 的操作、结果和耗时；不记录检索文本、抓取 URL 或响应内容。

## 接入示例

以下配置均已验证分组授权和成员自选两种方式。AnySearch 使用真实上游，其余样本使用受控协议夹具。请把 `.example.invalid` 地址、模型、租户和知识库标识替换成自己的服务值。每条上游的真实 Key 只填写在该上游的「平台凭据」中；`{credential}`、`{access-token}` 和 `{upstream:name}` 保持原样，由平台解析。

### AnySearch

包名：`@anysearch/anysearch-dsh`。添加上游 `search`，地址为 `https://api.anysearch.com`，请求头为 `Authorization: Bearer {credential}`，保存测试请求 `GET /v1/domains`。

添加环境变量 `ANYSEARCH_API_KEY`，值为 `{access-token}`。条目配置填写：

```yaml
web-search-anysearch:
  baseURL: "{upstream:search}"
  apiKeyEnv: ANYSEARCH_API_KEY
```

在 DSH 中将网页搜索提供者选为 AnySearch，再执行一次搜索。上游测试检查连通性，实际搜索用于验证插件调用链路。

### modsearch：Tavily 或 Exa

包名：`@liustack/modsearch`。添加以下两条上游：

| 名称 | 示例地址 | 请求头 |
| --- | --- | --- |
| `tavily` | `https://tavily.example.invalid` | `Authorization: Bearer {credential}` |
| `exa` | `https://exa.example.invalid` | `X-API-Key: {credential}` |

两条上游均保存测试请求 `POST /search`，JSON 请求体为 `{"query":"SAMPLE_READY"}`。实际验证的配置每次只启用一个搜索引擎，仅使用环境变量，条目 YAML 留空。从以下两列选择一种：

| 环境变量 | Tavily 配置 | Exa 配置 |
| --- | --- | --- |
| `TAVILY_API_KEY` | `{access-token}` | 留空 |
| `TAVILY_BASE_URL` | `{upstream:tavily}` | `{upstream:tavily}` |
| `EXA_API_KEY` | 留空 | `{access-token}` |
| `EXA_BASE_URL` | `{upstream:exa}` | `{upstream:exa}` |
| `FIRECRAWL_API_KEY` | 留空 | 留空 |
| `FIRECRAWL_BASE_URL` | `{upstream:tavily}/unavailable` | `{upstream:exa}/unavailable` |

“留空”指空值，不要填写“留空”这两个字。在 DSH 中将网页搜索提供者选为 modsearch，再执行搜索。上述配置不给 Firecrawl 提供 Key，Firecrawl 不可用。本次验收未覆盖同时启用 Tavily 和 Exa 的配置。

### dsh-image-gen：OpenAI 兼容服务

包名：`dsh-image-gen`。添加上游 `image`，地址为 `https://images.example.invalid`，请求头为 `Authorization: Bearer {credential}`，保存测试请求 `GET /v1/models`。添加环境变量 `DSH_IMAGE_GEN_OPENAI_COMPAT_KEY`，值为 `{access-token}`。条目配置填写：

```yaml
image-gen:
  provider: openai-compat
  openaiCompatBaseURL: "{upstream:image}/v1"
  openaiCompatModel: YOUR_IMAGE_MODEL
  saveToWorkspace: false
```

模型名称请使用上游实际支持的值。已验证的调用包含图片生成、multipart 图片编辑、附件摘要，以及超过 65 秒的上游等待。

### WeKnora：固定租户与资源句柄

包名：`@wxg-prc-cpg/dsh-weknora`。添加上游 `weknora`，地址为 `https://weknora.example.invalid`，请求头为 `X-API-Key: {credential}` 和 `X-Tenant-ID: YOUR_TENANT_ID`，保存测试请求 `GET /api/v1/knowledge-bases`。不需要环境变量，条目配置填写：

```yaml
weknora:
  baseUrl: "{upstream:weknora}/api/v1"
  apiKey: "{access-token}"
  tenantId: YOUR_TENANT_ID
  knowledgeBaseIds:
    - YOUR_KNOWLEDGE_BASE_ID
  resourceUrls: handle
```

固定上游请求头和条目配置中填写同一个租户值。即使成员提交其他值，实际转发仍由上游固定请求头决定。验收覆盖 `weknora_ask`、SSE 响应和资源句柄，并验证伪造的认证头、租户头和 Cookie 被丢弃。平台不改写上游响应中的 URL。

## MCP 服务

MCP 服务向 agent 提供工具定义，在「MCP 库」单独管理。添加服务不会自动授权或上架。

### 从 MCP 广场引入

打开「MCP 库 → MCP 广场」，查看平台维护的 MCP 服务。高德只需填写服务名与高德 **Web 服务**类型 Key，再点击「引入 MCP 服务」。平台将 Key 保存为只写凭据并测试连接，服务列表中的进度在刷新后仍保留。失败或中断的引入暂不可用，可重试或删除；平台重启会将中断测试标为失败，由管理员明确重试。

成功引入不会自动授权、上架或启用服务。之后可授权给分组，或上架到成员应用中心。管理员隐式获得访问权，自己的服务默认停用。使用不同名称可明确引入独立副本，同一次引入的重复提交不会创建另一条服务。

广场服务的地址、运行方式与认证配置由平台维护，不能编辑；名称、凭据、授权、上架状态、必选策略和停用工具仍可管理。修改凭据后需重新测试通过才可用。手动添加及 JSON 导入服务保持可配置，不按名称自动转为广场服务。每份服务记录采用的广场版本。

**12306** 服务无需 Key。填写名称后，平台在共享准备容器中下载并校验固定源码包，再按锁文件安装依赖，自动展示准备和连接测试进度。详情中可查看准备日志，失败时点击「重试引入」。刷新不会重复准备；重启保留准备记录，将中断引入标为可重试，已有就绪依赖会复用。每位启用服务的成员各有隔离的按需进程，不挂载成员文件。实际车票查询仍取决于提供方网络可用性和预售日期范围。

平台升级带来新版广场服务时，在已引入服务选择「查看广场更新」，比较版本及连接配置。平台升级不会自动覆盖已采用配置。候选在后台准备、测试，原服务继续可用；失败保留原服务，可从同一入口重试；成功后成员下一次请求使用新版。服务名、凭据、授权、发布状态、必选规则、停用工具和成员选择保持。并发编辑或凭据轮换会使候选失效；重启后中断更新显示失败，需要管理员明确重试。新增必要凭据必须先补齐再验证。

### 选择运行位置

| 运行位置 | 适用场景 | 凭据与成员文件 |
| --- | --- | --- |
| 远程服务 | 提供方已有 Streamable HTTP MCP 地址 | 网关附加平台凭据，不挂载成员文件 |
| 共享运行 | stdio 命令需要平台凭据，不需要成员文件 | 每位成员使用隔离容器中的独立进程，只读加载已准备依赖，不挂载成员 home 或工作区 |
| 成员容器运行 | stdio 命令需要成员工作区，例如浏览器或文件工具 | 在该成员容器内运行，禁止使用平台凭据 |

「共享运行」指平台托管执行，不代表成员共用一个 MCP 会话。它使用平台代执行的并发、超时和容器资源限制，空闲进程会被回收。连接测试使用独立进程，关闭测试不会关闭管理员的成员会话；该进程同样占用执行名额。检测到 Podman 时始终使用容器；仅在 Podman 不可用时，开发执行才退化为宿主进程，并提示未隔离。既需要平台凭据、又需要成员文件的服务需要「成员独立运行」，目前不可用。

共享进程空闲 5 分钟后回收。回收后，下一次调用会在原 DSH 会话自动恢复连接，无需关闭再开启服务。每次恢复最多尝试一次，握手上限为 30 秒；失败后可再次发起调用。只有明确因会话失效而未执行的请求会在恢复后重发一次。连接中断导致结果未知时不会自动重放，涉及写入或其他副作用时，请先确认上游执行结果。

执行中的请求不会因静默而被当作空闲回收。共享客户端遵循平台配置的请求期限，避免官方客户端较短的默认超时提前取消有效请求。代执行超时分别限制启动和每次请求，不再限制整个共享进程的总存活时间。超时或取消会终止该进程，后续调用可以重新连接；并发、CPU、内存及 PID 限制继续生效。工具视图记录远程或共享运行 MCP 工具调用的结果，包括失败和被拒，不记录参数或结果内容；进程生命周期事件不单独产生工具使用记录。

### 添加、准备与测试

1. 添加以 `p-` 开头的服务名及描述，选择远程地址，或填写命令、参数、环境变量并选择运行依赖。
2. 远程服务的密钥填写在「平台凭据」，在固定请求头或查询参数中用 `{credential}` 引用，例如 `Authorization: Bearer {credential}` 或查询参数 `key={credential}`。命名凭据用 `{credential:name}` 引用。共享命令可在环境变量值中使用这些占位符。不要把 Key 写进地址、命令参数或准备命令。
3. 先在「运行依赖」准备依赖，再为两种命令运行位置选择已有可用版本。声明的目录按选择顺序组成 PATH；`{dependencies}` 指向迁移服务自身的依赖目录，或首个选中依赖。准备过程不接收平台凭据，凭据仅在共享服务启动时注入。准备失败保留最后可用版本及迁移回退产物；查看日志后点击「重新准备」。广场依赖定义只读，运行时调用不会安装包。
4. 点击「测试连接」发现工具。测试不会为管理员启用服务；成员容器测试会启动管理员本人的实例。工具列表是快照，上游变化后应重新查看。
5. 勾选要停用的工具并保存。新发现的工具默认可用。上架给全部成员前，必须先通过连接测试。
6. 在分组详情中授权，或上架供成员自选。含平台凭据的服务上架后，全部成员都能通过该服务使用凭据；确认前应检查授权范围。

「导入 MCP JSON」预览 `mcpServers` 中的 `url`/`type`/`headers` 或 `command`/`args`/`env` 配置，必须逐条检查并保存。疑似密钥会移入凭据字段等待确认，但识别并不完整，仍需检查全部字段。导入命令默认采用共享运行。`sse` 类型按 Streamable HTTP 处理，不支持旧式 HTTP+SSE 传输。

### 成员使用与生命周期

MCP 凭据及固定请求头、查询参数、环境变量的值在页面与管理接口中只写不回显。留空保留已存值，明确移除凭据或删除具名行才会清除。含已配置秘密的命令、参数或地址也会隐藏；删除其他参数时，未修改的受保护参数仍对应原来的位置。准备命令不能包含运行凭据。成员启动文件仅携带服务身份及 generation，获授权的运行进程启动命令时在内存中获取当前调用配置。

保留的秘密字面值在凭据轮换、清除及重启后仍受保护；不能转入成员运行或准备命令。改变该边界时，先替换或移除这些引用。

在 DSH 内打开「平台应用 → MCP 服务」。普通分组与管理员分组都需要显式授权，授权服务默认启用。成员可以停用非必选授权服务，并启用或移除自己的上架自选。必选只对通过授权获得服务的成员锁定启用，包括管理员；仅上架不会强制成员启用。

MCP 工具定义占用模型上下文，可停用暂时不用的非必选服务来减少占用。变更无需重启成员实例，工具在 agent 下一轮请求时更新。MCP 同名冲突时，生效中的平台条目优先；成员自配条目保留，平台不再接管后恢复可用。

取消上架清除成员自选，保留分组授权。移除服务清除其授权、自选和保存的凭据。失去全部使用权限或账户被停用后，后续网关请求会被拒绝。共享进程会在权限或配置变化后停止；远程凭据变化在下一次请求时生效。环境重置保留平台授权和自选。

### 鉴权与信任边界

仅支持 OAuth 的服务暂不可用；提供方有 PAT 或 API Token 方案时，可改用该方案。平台不代办共享或成员个人 OAuth 登录。不支持 AWS SigV4、TC3 等签名鉴权。凭据按配置附加到请求头、查询参数或共享进程环境变量，不会逐请求签名。不支持的凭据模板无法通过校验。

获授权成员可以用自己的成员令牌，在 DSH 界面之外调用平台网关。这是使用上游凭据的权限，不是读取凭据值的权限。平台凭据值不会进入成员环境、配置或共享进程的命令参数；只有隔离共享进程接收其配置的秘密环境变量。提供凭据前应审查第三方命令行为；过滤工具不能让不可信服务变得安全。

成员容器命令禁止使用平台凭据，包括凭据模板。原成员进程轮换环境值仍可保留受保护参数；从共享或远程切到成员运行时，命令、参数和环境中不得残留原平台凭据。其文件、环境和进程均可被该成员访问，因此这里的工具过滤只用于使用体验，不是安全边界。平台不禁止成员自行配置 MCP 服务，也不为直接访问提供密钥。

## 生命周期

版本变更保留上游和接入配置。新版本缺失的条目 ID 会被标记为失效，这些条目不应用改写，其余条目和环境变量继续应用。

取消发布清除只读自选，保留分组管控。移除插件清除上游、凭据、接入配置、两份分组清单及只读自选。两种操作都保留成员原生副本、设置及交付历史；选用库版本不升级原生副本。加载变化在重启后生效；撤权或取消发布导致成员失去全部授权时，下一次上游调用立即被拒绝。停用账户也会立即阻止后续调用。

系统升级保留平台接入数据。重置环境清除原生副本及成功预装记录，随后按当前分组清单预装一次；自选原生插件不自动恢复。只读自选及接入配置保留。完整行为见[分组与插件](install.zh-CN.md#分组与插件)。

## 接入边界

插件必须支持通过环境变量或配置修改服务地址，并通过请求头携带 Key。平台提供通用转发，不为插件编写专属适配。

平台不强制所有流量走网关，不锁定成员设置，不接管自装插件，不改写上游响应中的 URL。网关记录覆盖平台上游、远程或共享运行 MCP 工具调用；插件本地工具和成员容器 MCP 不计自报，详见[使用记录](install.zh-CN.md#使用记录)。成员可以修改自己的接入配置；直接访问第三方服务时须使用自己的 Key。获授权成员可以用成员令牌调用平台上游，这种使用权限不等于读取平台凭据的权限。

## 成员插件贡献

成员可以让 agent 检查插件，再使用 `submit_contribution` 并指定
`kind: "plugin"`。已安装的包源插件提交包名与精确版本；本地目录在成员实例内
打包为 TGZ，上限 50 MB。确认卡片列出来源、包标识、文件列表与排除的私有文件。
成员点击**提交**后才开始上传。

平台在私有区域保存包，并在隔离容器中检查清单、仅来自包源的依赖与离线激活。
bundle patch 无效或激活失败时拒收。成员的原生插件详情页提供**贡献到平台**，
用于开启带有可编辑检查请求的新会话，并展示最近一次贡献的状态、时间、原因与
待处理时的撤回操作。

管理员从**插件库 → 成员贡献**审阅用途、文件列表、`package.json` 与 bundle patch。
采纳需要重新确认影响范围，并生成独立的平台副本。新插件不会自动发布或授权。
技能和插件贡献共用每位成员 20 份待处理的上限；同名插件重交会替换本人原先的
待处理副本。

贡献的 `plugin` 声明包括 `upstreams`（名称、地址、请求头模板、可选测试请求）、
`environment`（变量名、是否为秘密、用途、申请方式）及 `entriesYaml`。
用 `{upstream:名称}` 和 `{access-token}` 引用接入，不能包含真实凭据。
条目 ID 必须存在于 bundle patch。声明沿用管理员手填接入配置的规则，
拒绝保留或重复的变量名、不支持的 YAML、未知条目及上游引用。

声明的上游没有任何配置引用时会被拒收，并提示将地址改为可配置。
确需直连公开服务时可写 `directReason`，平台保留警告。安装脚本不会执行；
未声明的外部域名、过大包和疑似凭据要求成员审阅并明确保留警告。
私钥与高置信度凭据（包括 bundle patch 中的明文 token）会被拒收。
移除秘密、改用平台上游后重新提交。

采纳分三步：审阅文件与检测结果；核对预填上游、接入配置并填写平台凭据；
选择是否授权分组或发布。上游测试使用草稿而不保存，响应中回显的凭据会被隐藏。
带凭据发布时须明确确认所有成员可使用平台凭据。已有配置和只写凭据保留，
只预填新增声明项，删除项标出供管理员决定。最后确认才应用这些选择。
若采纳期间其他管理员的修改使接入配置或发布无法应用，采纳完成并给出警告，
该项留待管理员修复。

新贡献条目的维护人为贡献者。已有条目若没有维护人，采纳时默认保持为空；
管理员可勾选**将贡献者设为维护人**。只有当前维护人可提交更新；其他成员
以及复用同名用户名的新账户会被拒绝，并获知维护人名字。插件更新的精确
semver 必须高于当前选用版本，小修改可以增加补丁号；待处理副本可同版本重交。

审阅会显示包内文件的新增、修改、删除以及声明前后差异。已有凭据和接入值
保留，只预填新增字段；移除项标出并保留，直到管理员决定清理。每次采纳
记录提交者、时间及成员贡献或管理员来源。可在**基本设置 → 维护人**转交或
清空维护人。管理员直接替换版本保留维护人。平台应用中心与原生插件详情
显示贡献署名，采纳时可选匿名。

发布前测试原生插件时，先在原生插件页卸载平台交付的版本，再安装自己的版本并配置。只有只读插件提供以下开关：已获授权且有同名本地安装的维护人可在原生插件详情的贡献分区开启**使用我的本地副本**，
重启实例后加载自己的同名插件；关闭后再次重启，恢复平台副本。
分组授权与其他成员不变。本地副本没有平台环境变量或条目接入配置，
也不能使用平台上游凭据；关闭开关后，在实例实际重启恢复平台副本之前
仍受此限制。开发时需要凭据可自行在本地配置，并将其排除在贡献文件之外。

# 0.1.33

## English

### First-run setup and recovery

After creating the first administrator, configure one shared provider and model or
skip directly to administration. Protected deployer defaults can prefill the form;
keys stay masked and the server retains saved values. Saving configures the model
without claiming a successful inference test. Existing deployments keep their normal
entry flow.

Initialization links now open from external pages. Master-key rotation rejects an
unselected or uninitialized database before entering maintenance. Recovery can also
restore the specific old initialization failure when no key change occurred.

### Application-center publication

Plugin, skill, skill-pack and MCP details share publication status and impact
confirmation. Publishing is separate from editing and saving, including for catalog
resources. Updates preserve the administrator's decision. Availability, incompatibility
pauses and automatic restoration intent are shown separately from publication.

The member application center now has **Plugins | Skills | MCP services** tabs.
Skills keeps pack groups, expansion, details and whole-pack operations; administrator
skill-pack management remains available.

### MCP display and administrator access

Manual and catalog MCP services support display names and function descriptions.
Catalog imports retain bilingual defaults; explicit service updates refresh defaults
and preserve administrator overrides. Display edits retain connection identity,
tools and member access. Duplicate display names show their technical service IDs,
and details always include the ID. Existing services are not automatically backfilled;
reimporting adopts the new display information.

Administrators see **Go to admin console** first in the DSH account menu. It opens
`/admin` in a new tab. Refresh DSH after a role change; management still checks the
current permission.

### Models and upgrade notes

The native identity prompt uses the readable name of the model actually selected,
including presets and child agents. Stable routing IDs remain in use. **Supports
reasoning effort** describes whether members can select an effort level; the field
and its default behavior are unchanged.

DSH remains pinned to `dsh-v0.2.2-rc.1`. Upgrades preserve accounts, member files,
resource libraries, group grants and member selections. Initial model setup does
not restart for an already initialized deployment. For an older failed rotation
before database initialization, first refresh the recovery executor with the current
installer, then inspect and recover the recorded operation:

```sh
sudo bash install.sh --upgrade bootstrap
sudo /opt/dsh-phalanx/current/start maintenance-status
sudo /opt/dsh-phalanx/current/start maintenance-recover
sudo /opt/dsh-phalanx/current/start maintenance-status
```

## 简体中文

### 首次初始化与恢复

创建首管理员后，可填写一家共享供应商及一个模型，也可跳过并直接进入管理后台。
部署者可用受保护的默认值预填表单；密钥只显示掩码，由服务端保留已保存值。
保存表示配置已保存，不宣称真实推理测试通过。已有部署保持正常进入流程。

初始化链接可以从外部页面打开。主密钥轮换在进入维护前拒绝尚未选库或初始化数据库
的部署；对旧版尚未发生密钥变更的确切初始化失败，也提供恢复入口。

### 应用中心上下架

插件、技能、技能包及 MCP 详情统一显示上架状态和影响确认。上下架独立于普通编辑
保存，广场资源同样可以独立操作，更新保留管理员决定。可用性、不兼容暂停及自动
恢复意图与上架状态分别显示。

成员应用中心保留「插件 | 技能 | MCP 服务」三个页签。「技能」继续提供包分组、
展开、详情及整包操作，管理员技能包管理入口保留。

### MCP 展示与管理员入口

手动及广场 MCP 服务可配置展示名称和功能说明。广场引入时保存双语默认文案，
显式更新服务时刷新默认并保留管理员覆盖。只改展示文案会保留连接身份、工具及成员
授权。同名列表附技术服务标识，详情始终可查标识。不自动回填旧服务，重新引入后
可获得新展示信息。

管理员在 DSH 账户菜单第一项看到「前往管理后台」，点击后新标签页打开 `/admin`。
角色变化后刷新 DSH 更新菜单，后台始终检查当前权限。

### 模型与升级说明

原生身份提示使用当次实际选择的模型可读名称，覆盖预设及子 agent，内部路由继续
使用稳定标识。「支持推理级别」说明成员是否可以选择推理强度，字段与默认行为不变。

DSH 继续固定为 `dsh-v0.2.2-rc.1`。升级保留账户、成员文件、资源库、分组授权和
成员选择；已初始化部署不会重新进入首次模型配置。如果旧版在数据库初始化前轮换
失败，先用当前安装器刷新恢复执行器，再查看并恢复已记录的操作：

```sh
sudo bash install.sh --upgrade bootstrap
sudo /opt/dsh-phalanx/current/start maintenance-status
sudo /opt/dsh-phalanx/current/start maintenance-recover
sudo /opt/dsh-phalanx/current/start maintenance-status
```

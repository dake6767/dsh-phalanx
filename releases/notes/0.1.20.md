# 0.1.20

## English

Administrators can assemble **experts** from a shared model, plugins, skills,
skill packs and MCP services, then grant them to groups or publish them in the
application center. Members can summon an expert and start a conversation with
its persona, base tools and selected model. Their existing global capabilities
remain available in expert conversations.

Summoning an expert grants use of all its referenced capabilities, including
platform credentials. Dismissing an expert or losing its grant withdraws that
access immediately at the gateways. Instance restart applies changes to loaded
presets. Conversations started before a restart retain their loaded definition;
after restart, existing and new conversations use the current definition.
Unavailable references stay visible so administrators can repair them.

See the [expert guide](../../docs/experts.md) for setup, access boundaries and
conversation behavior. DSH remains pinned to `dsh-v0.2.1-rc.2`.

### Upgrade from 0.1.19

Use the normal verified update path from formal 0.1.19. Existing group grants,
member selections, skill packs and MCP access are preserved.

## 简体中文

管理员可将共享模型、插件、技能、技能包和 MCP 服务组建成**专家**，授权给分组，
或发布到平台应用中心。成员召唤后，可直接开始带有人设、基础工具和指定模型的
专家对话；成员原有的全局能力在专家会话中仍然可用。

召唤即获得专家引用的全部能力的使用权，包括平台凭据。解散或失去授权后，
网关立即收回经该专家获得的使用权；已加载的预设在实例重启后更新。
重启前已开始的会话保持已加载的定义，重启后新旧会话都使用当前定义。
不可用的引用保留显示，便于管理员修补。

组建步骤、使用权边界与会话行为见[专家指南](../../docs/experts.zh-CN.md)。
DSH 继续固定为 `dsh-v0.2.1-rc.2`。

### 从 0.1.19 升级

从正式 0.1.19 按常规校验升级流程更新。已有分组授权、成员自选、技能包和 MCP
授权保持不变。

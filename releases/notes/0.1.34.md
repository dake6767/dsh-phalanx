# 0.1.34

## English

### Upgrading from v0.1.33

Update the upgrade executor once before preparing the upgrade in **System update**. The v0.1.33 executor cannot read the new module inventory. Download the v0.1.34 installer and run:

```sh
curl -fsSLo install.sh https://raw.githubusercontent.com/dake6767/dsh-phalanx/v0.1.34/install.sh &&
  sudo bash install.sh --upgrade bootstrap --version v0.1.34 --output json
```

The platform stays running while the executor updates. When the command reports `updater-ready`, return to **System update**, check again and prepare and apply the upgrade.

### Installation and deployment commands

The installer starts in Simplified Chinese and offers English on the first screen. It asks for the download source before looking up a version, then uses the server IP and port to suggest a browser address. You can edit the settings from the review screen. On a LAN deployment, explicitly declaring that there are no additional public inbound mappings lets members reach the internet through the platform proxy. Declare any public inbound mappings so the proxy can block connections back to the host.

Use `sudo dsh-phalanx start`, `stop`, `status` and `uninstall` to manage an installed deployment. Stopping interrupts member tasks and preserves data and the boot setting. Uninstall removes the program and service while keeping the files, database, configuration and matching key needed for reinstall. Review the listed paths before choosing explicit data removal.

### Members, plugins and groups

Administrators can start or restart individual member instances. The **Switch to this member’s DSH** action requires the target member’s password and keeps the administrator account available in the browser’s account list.

Members can apply verified updates to eligible platform-delivered plugin copies, including verified content changes at the same version. Updates retain settings and enabled state and try to restore the previous copy on failure. After a successful update, members can restart DSH or continue working.

The group’s **Feature settings** tab includes **Show Platform App Center**. It starts off for every group, including existing and administrator groups. Members see the current setting on refresh and can continue to use their existing resources while the App Center is hidden.

New accounts use stable user-space directories. Existing accounts keep their current directory and files. DSH remains pinned to `dsh-v0.2.2-rc.1`.

## 简体中文

### 从 v0.1.33 升级

在「系统升级」中准备升级前，先更新一次升级执行器。v0.1.33 的执行器无法读取新版模块清单。请下载 v0.1.34 安装器并运行以下命令。

```sh
curl -fsSLo install.sh https://raw.githubusercontent.com/dake6767/dsh-phalanx/v0.1.34/install.sh &&
  sudo bash install.sh --upgrade bootstrap --version v0.1.34 --output json
```

执行器更新期间平台持续运行。命令返回 `updater-ready` 后，回到「系统升级」重新检查，再准备并应用升级。

### 安装与部署管理

安装器默认使用简体中文，首屏可选 English。在查询版本前先选择下载源，再按服务器 IP 和端口生成建议访问网址，确认前可返回修改。局域网部署明确声明没有额外公网入站映射后，成员仍可通过平台代理访问互联网。有实际公网入站映射时请完整填写，以便平台代理拦截回连宿主的请求。

已安装部署可通过 `sudo dsh-phalanx start`、`stop`、`status` 和 `uninstall` 管理。停止会中断成员任务，并保留数据与开机自启设置。卸载默认移除程序和服务，成套保留重新安装所需的文件、数据库、配置和匹配密钥。选择彻底清理前可核对列出的影响路径。

### 成员、插件与分组

管理员可以单独启动或重启成员实例。「切换到该成员 DSH」需要目标成员的密码，管理员仍可从浏览器的已登录账户列表切回。

成员可以主动更新符合条件的平台交付插件副本，涵盖同版本的已核实内容变化。更新保留设置和启停状态，失败时会尝试恢复旧版。更新成功后，成员可选择重启 DSH 或继续工作。

分组「功能设置」新增「展示平台应用中心」，新分组、存量分组和管理员分组默认关闭。成员刷新页面后看到当前分组的设置，应用中心隐藏时仍可使用已有资源。

新建账户使用稳定的用户空间目录，已有账户保留原目录与文件。DSH 继续固定为 `dsh-v0.2.2-rc.1`。

# 0.1.7

- Add single-group account membership, a default group for ordinary accounts and a protected administrator group. Role and group changes remain atomic.
- Add an administrator plugin library for exact npm versions and private `.tgz` archives, with isolated dependency preparation and offline activation checks.
- Grant read-only managed plugins to groups. Changes take effect on the next member restart, with pending counts and an explicit action to restart affected members.
- Add Platform apps to the DSH sidebar, using native DSH controls and theme tokens. Members install and update their own copies; unpublishing preserves existing installations.
- Coordinate same-name managed and self-installed plugins, check replacement versions before selecting them, and revoke grants when removing a library plugin.
- Recheck plugin compatibility during system upgrades. Incompatible plugins keep grants while loading and publication pause. Environment reset clears member copies while retaining managed plugins.

- Unify account, group, plugin, model and system management page frames; keep plugin cards and add publication filtering.

Upgrade from formal 0.1.6 through **System settings → Check for updates**. Applying
the update restarts services and interrupts running tasks after confirmation.
Account schema advances from 4 to 5: ordinary accounts enter the default group and
administrators enter the administrator group. Existing account identities, user
spaces, conversations, projects, shared model settings and self-installed plugins
are preserved. The pinned DSH revision and environment epoch are unchanged.

Group grants are not an installation allowlist. The platform does not manage
plugin configuration or plugin keys. See the [installation guide](../../docs/install.md#groups-and-plugins)
for operation and recovery details.

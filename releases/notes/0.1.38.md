# 0.1.38

## English

### Changes

- Members can sign in and start a conversation while native plugin history loads in the background.
- After an abnormal exit, the platform recovers a DSH profile write lock when it can verify that the previous writer has exited. Locks with uncertain ownership are preserved.
- The plugin, skill, and MCP catalogs show purpose tags below the search field. Choose one tag and combine it with your search.
- DSH is pinned to `dsh-v0.2.2-rc.3`.

### Upgrade from v0.1.37

To upgrade from **System update**, first download the v0.1.38 installer and run `sudo bash install.sh --upgrade bootstrap --version v0.1.38`. The platform stays online while the updater is replaced. Return to **System update** to prepare and apply the upgrade. The v0.1.38 updater can verify ownership of a legacy DSH web profile lock while the predecessor still owns its mounts.

Use the same updater step when **System update** reports that an older supported installation needs updater v0.1.38.

## 简体中文

### 更新内容

- 成员登录后可以先开始对话，原生插件历史在后台加载。
- 成员实例异常退出后，平台会在确认原写入者已退出时恢复 DSH 配置写锁，归属不明的写锁会保留。
- 插件、技能和 MCP 广场在搜索框下方显示用途标签。可选择一个标签，与关键词一起筛选。
- DSH 固定为 `dsh-v0.2.2-rc.3`。

### 从 v0.1.37 升级

通过「系统升级」升级前，先下载 v0.1.38 安装器，执行 `sudo bash install.sh --upgrade bootstrap --version v0.1.38`。更新执行器期间平台保持运行。之后回到「系统升级」准备并应用更新。新版执行器会在旧版平台的挂载仍可读取时核对遗留 DSH 网页配置写锁的归属。

其他受支持的旧版若在「系统升级」看到需要 v0.1.38 执行器的提示，也请先按上述步骤更新执行器。

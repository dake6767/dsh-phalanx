# 0.1.26

## English

### Fresh installation required

This version requires a fresh installation. Existing deployments on v0.1.24 or earlier cannot upgrade in place. System update shows the release guidance without an apply action; the CLI refuses the unsupported upgrade. See the [installation and recovery guide](https://github.com/dake6767/dsh-phalanx/blob/main/docs/install.md#recoverable-system-updates).

Keep the old deployment and its verified backups before preparing a separate installation. There is no import of legacy SQLite or JSON platform facts. Export the account list and administrator configuration privately to guide reconfiguration; do not include keys in that list. Do not remove the old data until its retention and recovery requirements have been reviewed.

### Platform facts and storage

PostgreSQL is the source of truth for accounts, grants, skills, plugins, MCP, experts, catalog installations, contributions, usage and member storage settings. Protected integration values use envelope encryption; the master key and encrypted database connection remain outside the platform data root. A database backup alone does not replace the offline master-key backup.

Default member files and built-in PostgreSQL are separate from generated platform projections. Rebuilding an instance or its projections preserves the saved platform facts and member files. Retain uploaded skill/plugin/contribution artifacts when backing up or moving a deployment; a database reference cannot recreate an uploaded original. The [storage guide](../../docs/install.md#storage-layout) describes all five layers, external PostgreSQL, managed switching, key rotation and whole-host migration.

## 简体中文

### 需要全新安装

此版本需要全新安装。v0.1.24 及更早的部署不支持原地升级。系统升级页展示重装指引，不提供应用升级操作；CLI 拒绝不支持的升级。请参照[安装与恢复指引](https://github.com/dake6767/dsh-phalanx/blob/main/docs/install.zh-CN.md#recoverable-system-updates)。

另行准备全新安装前，保留旧部署及核验过的备份。本版不导入遗留 SQLite 或 JSON 平台事实。可私下导出账户名单和管理员配置清单，用于重新配置；清单不要包含密钥。确认留存和恢复要求前，不要删除旧数据。

### 平台事实与存储

账户、授权、技能、插件、MCP、专家、目录安装、贡献、使用记录及成员存储设置以 PostgreSQL 为唯一事实来源。受保护的集成值采用信封加密，主密钥及加密的数据库连接配置位于平台数据根之外。数据库备份不能代替主密钥离线备份。

默认成员文件与内置 PostgreSQL 独立于生成的投影。重建实例或投影会保留平台事实和成员文件。备份和整机迁移时须保留上传技能、插件及贡献的本机制品；数据库中的引用无法重新生成上传原件。[存储指引](../../docs/install.zh-CN.md#存储布局)说明五层存储、外部 PostgreSQL、托管切换、密钥轮换及整机迁移。

# 0.1.17

## English

This release separates DSH image identity from platform source identity, reuses
the exact image tested by native CI during candidate publication, and adds build
layer caching. Installation and update discovery use release assets without
GitHub API requests. Deployment downloads support the configured `HTTPS_PROXY`.
DSH is pinned to `dsh-v0.2.1-alpha.5`, including its Office skills. Shared model
configuration remains administrator-owned; custom plugin markets are unavailable.
Saved credential references now take precedence over launch environment values.
Remove a same-name saved override if it prevents access through the platform.

### Image reuse transition

Formal 0.1.17 candidates still build their own image because the supported
0.1.16 updater requires matching image and platform source commits. Production
reuse starts with 0.1.18 only when the supported source range begins at 0.1.17
or later. Explicit reuse rehearsals verify the transition but cannot be promoted.
A shared installed digest requires no image pull/import or additional image
space; cleanup preserves images referenced by the current or previous release.
GHCR cleanup preserves every image referenced by a formal release. After release,
candidate cleanup removes only candidate-owned images without retained references;
drafts and unrelated candidates remain.

### Before upgrading

The installed 0.1.16 updater rejects the new release asset inventory. Before
using System update, download the current installer as described in the
[installation guide](../../docs/install.md) and run:

```sh
sudo bash install.sh --upgrade bootstrap --version v0.1.17 --output json
```

This verifies and replaces only the small updater. The installed platform keeps
running and member data stays in place. Return to System settings, check again,
then prepare and apply the update when ready. Finish or recover any prepared or
interrupted update before bootstrapping. Back up platform and member data before
applying the update.

## 简体中文

本版将 DSH 镜像身份与平台源码身份分开，候选发布直接使用原生 CI 测过的镜像，
并启用构建层缓存。安装与升级从 Release 资产发现版本，不再请求 GitHub API；
部署下载支持配置的 `HTTPS_PROXY`。
DSH 固定为 `dsh-v0.2.1-alpha.5`，包含上游随附的 Office 技能。共享模型配置继续
由管理员管理，自定义插件市场不可用。
已保存的凭据引用现在优先于启动环境变量；如果同名保存值导致平台访问失效，
删除该引用即可恢复使用平台提供的值。

### 镜像复用过渡

0.1.17 正式候选仍自行构建镜像，因为受支持的 0.1.16 更新器要求镜像与平台的
源码提交一致。生产复用最早从 0.1.18 开始，并要求受支持的来源版本全部不低于
0.1.17。显式复用演练用于验证过渡，但演练候选不能晋级正式发布。
已安装的共用 digest 无需再次拉取或导入，也不占额外镜像容量；清理会保留当前
版本或上一个成功版本仍引用的镜像。
GHCR 清理永久保留任一正式版引用的镜像。正式发布后，候选清理只删除没有保留
引用的候选专属镜像；草稿和无关候选继续保留。

### 升级前

已安装的 0.1.16 更新器会拒绝新的 Release 资产清单。使用系统升级前，先按
[安装指南](../../docs/install.zh-CN.md)下载当前安装器，再执行：

```sh
sudo bash install.sh --upgrade bootstrap --version v0.1.17 --output json
```

这一步只校验并替换小型更新器，已安装平台继续运行，成员数据保留。完成后回到
系统设置重新检查更新，再准备和应用升级。如已有准备完成或中断的升级，须先完成
或恢复；应用升级前请备份平台与成员数据。

# 0.1.11

## English

0.1.11 improves file downloads, Office and HTML previews, service previews and the administrator UI. See the [release acceptance record](https://github.com/dake6767/dsh-phalanx/releases/download/v0.1.11/acceptance.md) for the accepted artifact identities, checks and limitations.

- Office previews include redistributable Chinese and Latin fonts: Noto CJK, Liberation, Carlito and Caladea. Missing faces use the converter's substitutions; layout can differ from the original application's rendering. Existing files need no edits. The new instance image and preview configuration take effect after upgrade and instance replacement; reopening an old preview refreshes its conversion cache.
- Delivery cards and the preview toolbar download the **current original file**, including files without a preview. A file changed since the chat reply downloads its current bytes. Missing, inaccessible or interrupted files report failure. Preview PDFs are not substituted for source documents.
- HTML/HTM files open with script interaction by default, independently of the development-view switch. Each preview uses an isolated opaque iframe; platform cookies, parent UI and shared browser storage are unavailable. Closing and reopening resets in-frame state.
- **Service preview** opens a prefix-aware temporary HTTP application running in your own instance. Assets, API requests and WebSocket hot reload are supported. Use the displayed agent instructions and keep the application prefix private: it contains a scoped preview credential. Login or instance changes require a new prefix. Redirects and Service Workers are unsupported. Applications needing browser cookies or persistent storage should keep state on their own server.
- The administrator UI keeps the existing member/plugin page framework and HeroUI components. Skill and plugin cards are more compact, omit member counts and the default unpublished badge, and retain useful failure/conflict states. Upstream test results appear below their actions. Plugin details use **Basic settings** and **Access settings** tabs with draft protection. System settings have consistent section spacing. **Platform App Center** is the shared name throughout; publication actions say **Publish to Platform App Center** and published cards say **Live in Platform App Center**. Skill/skill-pack tabs use compact, left-aligned HeroUI tabs.

The native account, App Center, download and preview features remain modules of the platform plugin and arrive with the platform upgrade; members install nothing separately. Module failures remain local. `/recovery` is independent of the native DSH page.

### Upgrade and service preview

The supported source is 0.1.10. DSH revision, account schema 5 and environment epoch 1 remain unchanged (compatibility protocol 1). Use the verified target installer for preparation and application, retaining the returned operation ID. Save work before applying: application stops running instances. The normal [upgrade and recovery instructions](../../docs/install.md#recoverable-system-updates) remain applicable.

Download and verify the target installer as described in the upgrade instructions, then prepare and apply the stable release:

```sh
sudo bash install.sh --upgrade prepare --version v0.1.11 --output json
sudo bash install.sh --upgrade apply --operation <prepared-operation-uuid> --yes
```


Service preview is optional. Configure a separate preview port and public origin alongside the platform origin, with the same hostname and scheme and a different port. Pure IP HTTP works; HTTPS needs a normally trusted certificate for both origins. See [service configuration](../../docs/install.md#private-http-service-previews). Start the application with the existing execution tools, listen on an allowed container loopback port, and adapt assets/API/WS to its displayed prefix. Do not expose a host/container port directly. Idle pages and connections do not keep instances alive; after reclamation, reopen the workspace, restart the application and reopen its preview. Logout, account revocation and instance replacement revoke existing access.

OpenCLI, Chrome, personal cloud browsers/VNC and the image-plugin subpath issue remain deferred. This release does not install or fix them.

## 简体中文

0.1.11 改进原文件下载、Office 与 HTML 预览、服务预览和管理界面。已验收制品身份、检查结果及限制见[正式发布验收记录](https://github.com/dake6767/dsh-phalanx/releases/download/v0.1.11/acceptance.md)。

- Office 预览增加可再分发的中英文字体：Noto CJK、Liberation、Carlito、Caladea。缺失字体沿用转换器替代规则，排版可能与原应用不同。旧文件无需重写；升级并替换实例后，新镜像和预览配置生效，重新打开旧文件会刷新转换缓存。
- 产物卡片和预览工具栏支持下载**当前原文件**，包括没有预览能力的文件。对话生成后修改过的文件下载当前内容；文件不存在、无权限或传输中断会报告失败，不会用转换出的 PDF 替代源文件。
- HTML/HTM 默认允许脚本交互，与开发视图开关解耦。预览使用独立的 opaque iframe，不能访问平台 Cookie、父页面或共享浏览器存储；关闭并重新打开会重置帧内状态。
- **服务预览**支持当前成员实例内、按前缀适配的临时 HTTP 应用，包括静态资源、API 和 WebSocket 热更新。按页面指引让助手启动服务；应用前缀含受限预览凭据，请勿分享。登录或实例变化后需重新获取前缀。不支持重定向和 Service Worker。依赖浏览器 Cookie 或持久存储的应用应把状态保存在应用服务端。
- 管理界面保持成员管理与插件管理现有框架，复用 HeroUI 组件。技能和插件卡片更紧凑，移除成员统计及默认“未发布”标签，保留失败、冲突等有效状态；上游测试结果置于对应操作区下方；插件详情收敛为“基础设置”“接入配置”，保留草稿保护；系统设置统一模块间距；公开名称统一为**平台应用中心**，发布操作为“发布到平台应用中心”，已发布卡片标注“已上线平台应用中心”；技能／技能包使用靠左、随内容宽度的紧凑 HeroUI Tabs。

原生界面中的账户、应用中心、下载和预览仍由统一平台插件提供，随平台升级，成员无需另装。局部模块故障不会带走其他模块；独立 `/recovery` 页面保留。

### 升级与服务预览

支持从 0.1.10 升级，DSH 修订、账户数据版本 5 和环境代次 1 不变，使用兼容协议 1。用已验证的目标安装器准备、应用升级，并保存 operation ID。应用阶段会停止运行中的实例，请先保存工作。继续遵循[升级与恢复指引](../../docs/install.zh-CN.md#可恢复的系统升级)。

按升级指引下载并校验目标安装器后，使用上方命令中的正式标签 `v0.1.11` 准备和应用升级。

服务预览为可选配置：在平台访问地址之外设置独立预览端口和 public origin，主机名、协议相同，端口不同。支持纯 IP HTTP；HTTPS 两个地址均需正常受信证书。具体配置见[服务预览指引](../../docs/install.zh-CN.md#私有-http-服务预览)。应用由既有执行工具启动，监听允许的容器回环端口，资源、API 和 WS 使用页面显示的前缀，无需直接暴露宿主或容器端口。闲置页面和空闲连接不保活；回收后请进入工作区、重新启动应用，再打开预览。退出、账户权限撤销或实例替换后原访问失效。

OpenCLI、Chrome、个人云端浏览器／VNC 以及图片插件子路径问题仍延期，本版不宣传已经安装或修复。

Checks ran with Node24.21.0 and pnpm11.19.0. Static/quick commands were `node scripts/check-docs.mjs`, TypeScript `--noEmit` for source and admin UI, ESLint, `node scripts/check-architecture-assets.mjs`, Vitest, `node scripts/build-service.mjs`, and the admin UI Vite build. Browser suites use `vitest.e2e.config.ts`; the installed fixture starts the archive's `start` entry and binds its expected source SHA and image digest. Private fixtures cover Office previews, administrator navigation, skills, languages and upstream feedback alongside public artifact, HTML, service-preview, native-market and recovery cases. Those private fixtures and execution logs are retained with checksum-bound local evidence; they are not published test assets.

Installed acceptance includes two members and one administrator, PPTX/DOCX/XLSX with Chinese/Latin text and font substitution, both original-file download entries, missing/non-previewable/interrupted files, HTML interaction independent of coding view, trusted HTTPS, HTTP/WS prefix handling and credential stripping, cross-member rejection, revocation, module failure isolation and the independent recovery page. Idle tests separately prove trusted user gestures renew activity while app traffic does not, and containers are actually reclaimed.

The upgrade fixture starts from the byte-identical accepted 0.1.10-rc.2 bundle (the bytes promoted as 0.1.10), installed with its original installer on an isolated Ubuntu 24.04 amd64 VM. It uses a private archive handoff and warms rootless user namespaces because the VM uses CPU emulation. It does not establish a new cold-start or clean-install result for 0.1.11. The emulated baseline needed a fixture-only official Office timeout override of900000ms after its default60000ms conversion timed out. The target font patch superseded that override and restored the converter default60000ms. Both the initial target conversion and reopening timed out under CPU emulation. Before further configuration changes, an authenticated RPC confirmed the upgraded provider had a new, nonempty cache generation. A supplemental VM-only runtime wrapper now inserts an official patch after the managed overlays and before application arguments with the same fontDirectories and timeoutMs900000. The initial 2 GiB supplemental VM became unresponsive for an unconfirmed reason. After restarting the same disks with 4 GiB and restoring the manual mounts, the complete supplemental test passed in 377.49 seconds: accounts, models, groups, grants, skills, selections and source bytes were retained; the old Office file rendered Chinese/English text, downloaded byte-identically, and the platform plugin remained protected. The default upgraded cache generation was verified before this wrapper/restart; the later supplemental generation is recorded separately. These environment adjustments establish neither a minimum-memory requirement nor formal reboot acceptance, and do not turn the default-deadline failures into passes. Unchanged overlay bytes do not imply unchanged effective configuration. Native Linux installed Office checks used the production defaults. A separate actual nftables test passed admission blocking and reopening for platform, private gateway and preview ports; it does not claim continuous packet observation throughout an upgrade or reboot.

The owned test VM disks, SSH tunnel and test certificate were removed after acceptance, reclaiming about 20 GiB. The final platform/OCI archives, shared VM base and four existing host containers were preserved.

Formal hosted CI, Candidate publication, 0.1.11 clean-install acceptance and release promotion remain separate gates. No tag, release, deployment to an existing service or repository visibility change was performed. OpenCLI, Chrome, personal browsers/VNC and image-plugin compatibility remain deferred.

## 简体中文

本记录对应本地验证包，不表示已经发布 Candidate、通过 GitHub Actions，或具备正式版本晋升资格。发布说明已准备，外部发布另行执行。制品及源码身份见上表。

后续仅含交付文档的提交不改变本记录固定的代码／制品身份。

镜像仅更新 OCI LABEL，使提交身份符合安装器与最终平台源码一致的要求；19 个文件层、实际 blob、rootfs diff ID 和其他运行配置完全相同。镜像由先前构建的 0.1.10-rc.1 运行时镜像和本版字体脚本构成，实际派生配方及所有 OCI blob 均有校验。镜像构建之后的改动仅涉及平台 CSS 和测试，镜像配方、字体、依赖锁及运行时版本未变。平台包复用的 Node 和生产依赖已逐文件比较内容、权限及符号链接，与已验收 0.1.10 完全一致。此本地构建不替代正式 Candidate 流程。

最终组合通过文档、源代码和管理端类型、架构／资产检查及服务／界面构建；Linux quick 112个文件317项、CI浏览器16个文件19项、安装态浏览器10个文件13项、CPU4倍限速回收2项均通过。实际 0.1.10 prepare/apply、旧文件预览及下载补充检查、三端口门禁与环境清理均通过。命令、测试输入与边界见上表及英文说明。

安装态覆盖管理员与两位成员、三种Office格式及字体替代、两处原文件下载、不可预览／缺失／中断反馈、独立HTML交互、正常受信HTTPS、HTTP／WS前缀与凭据过滤、跨成员隔离和撤权、模块故障隔离及独立恢复。空闲测试单独验证真实手势续期、应用流量不续期及实际容器回收。

升级起点为已验收、后续原字节晋升到正式 0.1.10 的 rc.2 包，在独立 Ubuntu 24.04 amd64 虚拟机上使用原安装器安装。验收通过私有归档交接，CPU 模拟环境预先准备 rootless 用户映射；不据此声称 0.1.11 冷启动或干净安装已经验收。模拟基线在默认60000ms下转换超时，因此测试通过官方配置把旧版时限设为900000ms；目标字体patch覆盖该配置，恢复默认60000ms；目标首次转换与重开均在模拟环境超时。配置调整前，真实认证RPC已确认升级后缓存代次非空且已变化。现以VM专用运行命令wrapper在受管overlay之后、应用参数之前插入官方patch，保持相同 fontDirectories 并延长为 900000ms。首次 2 GiB 补充环境失去响应，原因未确定；保持同一磁盘、增至 4 GiB 重启 fixture 并恢复手动挂载后，完整补充测试在 377.49 秒通过：账户、模型、分组、授权、技能、自选状态及原文件字节均保留，旧 Office 文件中英文显示正常、下载字节一致，平台插件保护有效。默认升级后的缓存代次已在 wrapper／重启前验证，后续补充运行的代次单独记录。该调整不建立最低内存要求或正式重启验收结论，也不将默认时限的两次失败改记为通过。相同overlay文件不等于相同有效配置；真实Linux安装态Office验收使用生产默认值。另以真实 nftables 验证平台、私有网关及预览三个端口的关闭和重新开放，均通过，不声称全程观测升级或重启期间的每一个数据包。

验收后已清理本轮虚拟机磁盘、SSH 隧道和测试证书，回收约 20 GiB；最终平台／OCI 归档、共享虚拟机基盘及宿主上原有四个容器保留。

正式托管 CI、Candidate 发布、0.1.11 干净安装及正式版本晋升仍为独立门禁。未创建远端标签或 release，未部署到既有服务，未改变仓库可见性。OpenCLI、Chrome、个人浏览器／VNC 和图片插件兼容问题保持延期。

# Upgrade to 0.1.2 from 0.1.1

Stop work and retain a consistent private backup of platform state, protected configuration and user storage. Use the new installer to move a managed 0.1.1 installation into 0.1.2. Existing ports, storage bindings, credentials and account identity are retained. Applying immediately restarts the service, interrupts running tasks and may lose unsaved content. Interactive application asks for confirmation; noninteractive application requires `--yes`.

```sh
sudo bash install.sh --version v0.1.2 --yes
```

The installer introduces the root update executor and recoverable update protocol. Existing pending 0.1.1 first-entry preparation remains unchanged. Legacy manifests are recognized only for historical 0.1.0/0.1.1 formats; an undeclared legacy upgrade cannot use link-only rollback. Retain the verified backup and journal if recovery fails. Use the [server recovery instructions](../../docs/install.md#recoverable-system-updates).

## 从 0.1.1 升级

先停止工作，保存平台状态、受保护配置及用户存储的一致备份。使用新版安装器执行上述命令，将受管理的 0.1.1 升级至 0.1.2，保留端口、存储绑定、凭据和账户身份。应用会立即重启服务、中断运行任务，并可能丢失未保存内容；非交互执行必须传入 `--yes`。

安装器引入独立 root 更新执行器及可恢复升级协议；尚未完成的 0.1.1 首次进入准备保持原样。旧 manifest 只识别历史 0.1.0/0.1.1 格式，未声明的旧版升级不能只切换链接来回退。恢复失败时保留已验证备份和操作日志，按[服务器恢复说明](../../docs/install.zh-CN.md#recoverable-system-updates)处理。

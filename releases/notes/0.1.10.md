# 0.1.10

## English

- Add optional platform execution for library skills: multiple commands, blocked first arguments, independent secret/plain variables, isolated dependency preparation, administrator trial runs and execution records. Authorized members invoke original command names or script paths with platform credentials; credentials stay outside member spaces.
- Add global execution limits and 30-day audit retention. Preparation refreshes after skill, dependency-command, variable or runtime-image changes. Skill updates retain configuration; deleted skills clear credentials and prepared state while running invocations retain their artifacts until completion.
- Add skill packs, group grants and member selections, optional orchestration instructions, multi-skill ZIP review, public HTTPS Git import and manual update comparison. Member overrides and the existing management-page layout remain supported.
- Upgrade the pinned DSH runtime to `dsh-v0.2.1-alpha.2`. Upstream adds optional reasoning translation, Git worktrees, shared agent instructions and Claude Code/Codex subagents, plus font, work-detail and microphone preferences. It also improves streaming cancellation, settings refresh, previews, conversation titles, background workflows and subagent image input. Optional upstream features retain their own setup requirements; the platform does not enable them automatically.
- Use the bilingual notes as the formal Release body. See the [platform execution guide](../../docs/skill-execution.md) and [skill import/pack guide](../../docs/install.md#skills).

### Upgrade from 0.1.9

This runtime change uses compatibility protocol 2. The updater shipped in 0.1.9 cannot apply it through the old System settings flow. Download the target installer and run its two-stage preparation/application on the server:

```sh
curl -fsSLo install-0.1.10.sh https://raw.githubusercontent.com/dake6767/dsh-phalanx/v0.1.10/install.sh
sudo bash install-0.1.10.sh --upgrade prepare --version v0.1.10 --output json
sudo bash install-0.1.10.sh --upgrade apply --operation <prepared-operation-uuid> --yes
```

Save the operation ID returned by preparation. Preparation keeps the existing service running; application interrupts running tasks, so save work first. Use the same installer with `--upgrade status --output json` or `--upgrade recover --output json` when reconnecting or recovering.

Existing accounts, schema version 5, environment epoch 1, models, conversations, member files, skill grants and selections are retained. Platform execution starts disabled for existing skills, and skill packs start empty. New state uses separate platform carriers. Git is installed if the host lacks it.

Plugins are checked against the new runtime before platform loading. Incompatible plugins retain their original packages, grants and publication intent, but are not loaded or offered for selection until a compatible replacement is selected. In particular, tested `dsh-better-sidebar` versions 0.24.1 and 0.25.0 depend on the removed `webRuntime` service. The platform does not restore that removed service. Members manage incompatible native self-installed copies themselves.

### 从 0.1.9 升级

此次运行时变更使用兼容协议 2，0.1.9 自带更新器不能通过旧「系统设置」流程应用。请下载目标安装器，在服务器执行两阶段准备和应用：

```sh
curl -fsSLo install-0.1.10.sh https://raw.githubusercontent.com/dake6767/dsh-phalanx/v0.1.10/install.sh
sudo bash install-0.1.10.sh --upgrade prepare --version v0.1.10 --output json
sudo bash install-0.1.10.sh --upgrade apply --operation <prepared-operation-uuid> --yes
```

保存准备阶段返回的 operation ID。准备期间现有服务继续运行，应用阶段会中断正在运行的任务，请先保存工作。重新连接或恢复时，使用同一安装器的 `--upgrade status --output json` 或 `--upgrade recover --output json`。

保留已有账户、账户数据版本 5、环境代次 1、模型、会话、成员文件、技能授权及自选。已有技能的代执行默认关闭，技能包初始为空；新状态使用独立平台存储。主机缺少 Git 时会补装。

插件进入新运行时前会重新预检。不兼容插件保留原始包、授权和发布意图，暂停平台加载及市场展示，直到选用兼容替代版本。实测 `dsh-better-sidebar` 0.24.1 和 0.25.0 仍依赖已移除的 `webRuntime` 服务，平台不会恢复该服务；成员原生自装的不兼容副本需自行处理。

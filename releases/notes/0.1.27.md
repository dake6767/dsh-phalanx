# 0.1.27

## English

### In-place updates from v0.1.26

In-place upgrades resume with v0.1.26 as the minimum source. Earlier deployments
need a fresh installation and must retain their original data and backups.

The first v0.1.26 → v0.1.27 update needs one administrator step on the server.
Finish or recover any existing prepared or interrupted operation, download the
target installer and update only its verified small executor:

```sh
curl -fsSLo install.sh https://raw.githubusercontent.com/dake6767/dsh-phalanx/v0.1.27/install.sh
sudo bash install.sh --upgrade bootstrap --version v0.1.27 --output json
```

This leaves the v0.1.26 platform, data, image and platform PID in place. Return to
**System settings → System update**, check for updates, prepare the target and
confirm application. Applying interrupts running tasks. Later updates use the
installed executor directly while it meets the target's minimum reader and
required capabilities; this bootstrap is not a routine step for every version.

### Database recovery and member backups

Failed migration or validation automatically restores the registered PostgreSQL
schemas, keys, connection and deployment configuration, and database service unit
before restarting the previous platform. Built-in and external PostgreSQL use
archive tools matching the server's major version, prepared before downtime.
Unrelated database schemas remain outside recovery.

Member files are outside the upgrade backup. Administrators must keep their own
consistent user-root backup alongside the matching deployment set. Rebuildable
artifacts and projections stay in place. Temporary upgrade backups are removed
after success or completed restoration; recovery failure preserves them and keeps
maintenance closed. See the [backup and recovery guide](../../docs/install.md#storage-layout).

### Channels and compatibility

Candidate deployments can convert in place to a same-version formal release;
the normal upgrade transaction retains platform data and member files, and changes
the channel only after commit. Release declarations now describe schema ranges,
the upgrade floor, intermediate versions and the minimum reader. A sufficiently
recent reader tolerates future fields and higher protocol numbers. This release
keeps protocol 3 and the legacy accounts range for the v0.1.26 reader.

### Upgrade progress and maintenance

The system update card offers the action for its current state, including a
required intermediate version and conversion to formal. It shows localized phase
and error codes, recovery guidance, downtime and phase durations. Unknown errors
retain the original text and a restricted diagnostic log path. The apply dialog
explains task interruption and the separate responsibility for member backups.

During downtime, members see a maintenance page in English or Simplified Chinese
that refreshes when service returns. Member and resident instances remain closed
through validation. Status and check paths avoid starting a fresh platform process
for each request. See the [update guide](../../docs/install.md#recoverable-system-updates).

## 简体中文

### 从 v0.1.26 原地升级

本版恢复原地升级，最低来源为 v0.1.26。更早的部署须全新安装，并保留原数据与备份。

v0.1.26 首次升级到 v0.1.27 时，管理员须先在服务器执行一次前置操作。
先完成或恢复已有的准备中、准备完成或中断事务，再下载目标安装器，仅更新经过校验的小执行器：

```sh
curl -fsSLo install.sh https://raw.githubusercontent.com/dake6767/dsh-phalanx/v0.1.27/install.sh
sudo bash install.sh --upgrade bootstrap --version v0.1.27 --output json
```

该步骤保留 v0.1.26 平台、数据、镜像及平台 PID。随后回到「系统设置 → 系统升级」，检查更新、
准备目标并确认应用。应用会中断运行任务。后续只要现有执行器满足目标最低读者版本及所需能力，
就可直接升级；不需要每个版本都执行 bootstrap。

### 数据库恢复与成员备份

迁移或验证失败时，先自动恢复已登记 PostgreSQL schema、密钥、连接与部署配置、数据库服务单元，
再启动原平台。内置和外部 PostgreSQL 都使用与服务器主版本相同的导出恢复工具，在停机前准备完成。
无关数据库 schema 不在恢复范围内。

成员文件不进升级备份。管理员须自行制作一致的用户根备份，与匹配的部署组合保存。
可重建制品及投影原地沿用。升级成功或恢复完成后删除本次临时备份；恢复失败则保留，并保持维护隔离。
操作方法见[备份与恢复指引](../../docs/install.zh-CN.md#存储布局)。

### 渠道与兼容性

候选部署可原地转为同号正式版，正常升级事务保留平台数据及成员文件，提交后才更新渠道。
发布声明按 schema 区间、升级下限、断点和最低读者版本描述兼容性；满足最低读者的执行器容忍未来字段
和更高协议号。本版保留协议 3 及旧 accounts 区间，兼容 v0.1.26 读者。

### 升级进度与维护页

系统升级卡片按当前状态提供操作，包括先更新到断点及转为正式版，展示本地化阶段与错误码、恢复指引、
停机时长和各阶段耗时。未知错误保留英文原文与受限诊断日志路径。应用确认框说明任务中断及成员备份责任。

停机期间展示中英文维护页，服务恢复后自动刷新；验证完成前不启动成员及常驻实例。
status 和 check 路径避免每次请求都启动新的平台进程。详见[升级指引](../../docs/install.zh-CN.md#recoverable-system-updates)。

# 0.1.43

## English

### Changes

- Established an explicit four-layer dependency architecture (L0 standalone maintenance fence, L1 pure compatibility/protocol core, L2 host/operational adapters, L3 CLI/HTTP entry) across the Python installer and upgrade executor under `scripts/install/`, eliminating import cycles and duplicate top-level constant definitions in `install.sh`.
- Expanded all semicolon-chained and inline compound Python statements across `scripts/install/*.py`, `scripts/download-sources.py` and `scripts/dev/*.py` with zero runtime behavior changes, and regenerated `install.sh`.
- Added a zero-dependency Python standard-library static architecture and style gate (`scripts/check-python-architecture.py`) and `build-installer.mjs --check` to `pnpm lint`, backed by the shared `architecture-exemptions.json` size ratchet for legacy executor modules.
- Evolved the root executor inventory validation (`installer_executor_install.py` and `installer_executor_bootstrap.py`) from hardcoded historical module enumerations to a structured whitelist contract (up to 64 inventory files) while preserving the existing 23-module inventory and direct Web upgrades from `>=0.1.38` deployments.
- No runtime product feature or pinned upstream DSH version changes; existing deployments upgrade directly from supported prior releases.

## 简体中文

### 更新内容

- 为 `scripts/install/` 下的 Python 安装与升级执行器子系统建立显式四层依赖模型（L0 独立维护围栏、L1 纯逻辑与协议层、L2 宿主与运维适配层、L3 CLI/HTTP 入口层），彻底消除模块循环导入与 `install.sh` 共享全局命名空间内的重复顶层常量定义。
- 零行为变更展开 `scripts/install/*.py`、`scripts/download-sources.py` 与 `scripts/dev/*.py` 中全部分号多语句与单行复合语句体，清理未使用符号并同步重生成 `install.sh`。
- 新增零外部依赖的 Python 标准库静态架构与风格门禁（`scripts/check-python-architecture.py`）并连同 `build-installer.mjs --check` 接入 `pnpm lint`，存量超限执行器模块纳入根目录 `architecture-exemptions.json` 只降不升棘轮台账。
- 将升级执行器包校验（`installer_executor_install.py` 与 `installer_executor_bootstrap.py`）由硬编码历史名单枚举演进为结构化白名单契约（清单上限放宽至 64 文件），同时保持现役 23 模块清单与 `>=0.1.38` 部署的 Web 直接升级兼容不变。
- 本版不改动运行时产品特性与上游 DSH 固定版本，既有部署可从受支持的先前版本直接升级。

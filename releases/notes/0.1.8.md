# 0.1.8

## English

- Add plugin upstreams with administrator-owned credentials, fixed request headers and saved diagnostic requests. Authorized members call them with member tokens; real credentials remain in platform storage.
- Add access settings for instance environment variables and configuration merged by plugin entry ID. Access settings take effect after a member restart; upstream address, credential and header changes apply to the next request.
- Load both group-granted and member-selected platform apps read-only at the administrator's selected version. Members manage selections in **Platform apps**; group grants remain administrator-managed.
- Preserve upstreams and access settings across plugin version changes, system upgrades and member environment resets. Missing entry IDs are marked invalid. Revoking all access or disabling an account blocks the next upstream request.
- Use consistent platform-app terminology in the administrator interface and DSH integration. The native plugin page is unchanged.
- Allow up to five minutes for offline plugin activation during compatibility checks on slower hosts. The outer deadline for each preparation container stage remains ten minutes.

### Upgrade from 0.1.7

Use **System settings → Check for updates**. Preparing keeps the current service running. Applying the update restarts services and interrupts running tasks after confirmation.

Existing copies installed from the platform market in 0.1.7 remain native member copies. Platform apps identifies them as **Installed on the native plugin page**. To switch to a read-only platform selection, back up any personal settings or data required by the plugin, uninstall the old copy on the native plugin page, then install from **Platform apps** and restart the instance.

A same-name native copy yields while a platform app is eligible to load; its files are retained. When platform eligibility ends and the member restarts, the native copy can load again. Read-only platform entries are not guaranteed to appear as cards or detail pages on the native plugin page.

Account schema, the pinned DSH revision and the environment epoch are unchanged. See [Plugin access](../../docs/plugin-access.md) for setup and the supported connection boundaries. The platform does not enforce outbound routing or provide usage quotas.

### Sample acceptance

Both platform preinstallation and member selection passed for AnySearch `0.1.7`,
modsearch `5.10.6` (Tavily and Exa separately), dsh-image-gen `0.8.6` and WeKnora
`0.1.0`. AnySearch used its real service; the other upstreams were controlled
protocol fixtures. All ten combinations passed member-readable credential scans,
and all four samples passed immediate revocation checks. No plugin-specific
product adapter was needed. These results describe the sample gate; final release
acceptance is recorded separately.

## 简体中文

- 新增插件上游：管理员保存平台凭据、固定请求头和测试请求。获授权成员通过成员令牌调用，真实凭据保留在平台存储中。
- 新增接入配置：向实例注入环境变量，并按插件条目 ID 合并配置。接入配置在成员重启后生效；上游地址、凭据和请求头变更在下一次请求生效。
- 分组授权与成员自选的平台应用均按管理员选用的版本只读加载。成员在「平台应用」管理自选，平台预装由管理员管理。
- 更换插件版本、系统升级和成员环境重置均保留上游及接入配置。缺失条目 ID 会标记为失效；成员失去全部授权或账户停用后，下一次上游调用立即被拒绝。
- 管理界面和 DSH 集成统一使用平台应用相关术语。本版本不修改原生插件页。
- 慢速主机的插件离线激活检查允许等待五分钟；每个准备容器阶段的外层上限仍为十分钟。

### 从 0.1.7 升级

通过「系统设置 → 检查更新」升级。准备期间现有服务继续运行；确认应用更新后会重启服务，并中断正在运行的任务。

0.1.7 从平台市场安装的副本仍作为成员原生副本保留。「平台应用」会显示「已在原生插件页安装」。若要切换到只读平台自选，请先按插件说明备份需要保留的个人设置或数据，在原生插件页卸载旧副本，再到「平台应用」安装并重启实例。

具有平台加载资格时，同名原生副本暂时让位，文件保留；不再具有平台加载资格并重启后，原生副本可重新加载。不保证只读平台条目在原生插件页显示为卡片或提供详情页。

账户数据版本、固定的 DSH 版本及环境代次均保持不变。配置步骤与接入边界见[插件接入](../../docs/plugin-access.zh-CN.md)。平台不强制出网路由，也不提供用量配额。

### 样本验收

AnySearch `0.1.7`、modsearch `5.10.6`（Tavily 与 Exa 分别验证）、dsh-image-gen `0.8.6`、WeKnora `0.1.0` 均通过平台预装与成员自选两种方式。AnySearch 使用真实服务，其余上游使用受控协议夹具。10 个组合均通过成员可读位置的凭据扫描，四样本均通过即时撤权检查，无需插件专属产品适配。这些结果属于样本验收，最终发布验收单独记录。

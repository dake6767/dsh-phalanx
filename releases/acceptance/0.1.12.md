### Candidate and installation

Protected-main CI and the complete Candidate build passed. Full archive hashes,
image identity, source labels and all 6,061 installed files and symbolic links
matched the candidate. The image's pinned pnpm also ran offline as a non-root
keep-id user.

A pristine Ubuntu 24.04 amd64 VM passed installation, corrupt-package rejection,
retry, repeat-install idempotency, independent ext4 member storage and an actual
reboot with a changed boot ID. A fresh browser confirmed retained files and model
configuration, native terminal and streaming, and automatic service/storage
recovery. The model used a controlled protocol fixture.

### Native behavior and interface

The original native qualification invocation completed 24 files / 33 cases:
23 files / 32 cases passed, and the five-service combination failed during public
dependency preparation. Its original receipt remains retained. The complete corrected combination then passed in 370.36 seconds: five service
discoveries and ten semantic real calls across two members, with access changes
and credential isolation. Together the two invocations cover 24 original files /
33 distinct cases without double-counting retries.

Passed coverage includes shared and member MCP execution, credentials and access
fences, live grants and member choices, conflicting personal configuration,
changed-image re-preparation, retained formal 0.1.11 grants/selections/member files,
original downloads and interrupted transfers, interactive HTML isolation, HTTP
and trusted HTTPS previews, recovery and network isolation, and native skill
publication. Trusted HTTPS also passed Secure cookies, native streaming, WSS and
revocation. Administration navigation and language checks use source composition;
runtime-upgrade adapters use actual containers. This is a mixed qualification
suite, not a claim that every case exercised the installed CLI.

Default-configuration native Office conversion passed for mixed Chinese/Latin
PPTX, DOCX and XLSX. Original hashes remained unchanged and the provider generation
changed across the old/new image transition. Screenshots show readable text and
visible font-substitution warnings. The MCP administration screen retains the
existing sidebar, table and editing drawer; app-center desktop/mobile controls and
Chinese skill states remain readable.

### Public upgrade

The complete installed public-CLI upgrade from formal 0.1.11 to the exact candidate
passed in 2544.21 seconds. Prepare imported the accepted image; apply completed
successfully. Accounts, models, groups, grants, published skills, member selections,
home files and original Office bytes were retained. The platform plugin remained
active and read-only, and the installed service recovered with the exact candidate
platform and image identities.

Default-to-default provider generations changed across the upgrade. The supplementary
conversion of the unchanged PPTX also produced a new generation relative to both
the baseline default and baseline supplement, while retaining its file version and
original-download hash. Post-upgrade checks verified the actual runtime Office
configuration and blocking/recovery of all three maintenance ports. A fresh login
and readiness-checked screenshot confirmed installed/running candidate versions,
the successful upgrade operation and MCP navigation in the existing administration
layout.

The baseline was reconstructed with the original 0.1.11 installer and byte-identical
archives from the published stable release. Its private offline handoff uses the
original `v0.1.11-rc.1` manifest tag. The stable promotion record, source/run,
platform/image identities and full archive hashes establish equivalence to formal
0.1.11. The target uses the exact `v0.1.12-rc.1` candidate archives through the same
recorded private handoff; the transaction uses the public installer CLI.

The VM has four vCPUs and 4 GiB RAM without hardware acceleration. The old-file
conversion supplement extends only the Office deadline to 900000 ms while
preserving the product font directories. This is not a default-deadline conversion
claim for this VM or a minimum-memory/performance certification. Native Linux
Office qualification above uses the normal candidate configuration. Font
substitution does not promise pixel-identical rendering to the authoring application.

### Corrections and boundaries

The first hosted source CI attempt exposed a real-DSH skill test in the controlled
browser group. It moved to mandatory native qualification, where it passed; two
controlled MCP administration/import tests were added to CI. No required native
coverage was removed.

Initial clean-harness launches stopped before installation because dependency
resolution was missing. Their receipts were retained, the unchanged dependency
installation was linked, and the complete clean test passed. The first temporary
public upstream failed normal TLS preflight; it was retired and a fresh endpoint
passed certificate validation before product tests began.

Bocha's pinned uv bootstrap downloaded slowly from the default public registry.
A per-command TUNA index returned a wheel matching official PyPI size and SHA256;
source archive checksum, frozen lock, Python version and real provider endpoints
were unchanged. The first focused rerun passed Bocha preparation and connection
but failed while downloading full Chrome. The next private input uses the official
`--no-shell` option: the pinned MCP launches full Chrome for Testing, so its actual
browser remains unchanged and the unused headless-shell archive is omitted.
Runtime arguments, preparation deadlines and functional assertions remain intact.
A later rerun reproduced the fixed CPython archive download timeout. Increasing
only the download read timeout did not resolve it. Checksum-verified official
CPython and Chrome archives were transferred through temporary public-byte
relays; the Python-only preparation probe passed. Runtime provider requests still
go directly to their providers. The fresh full combination passed under the original product deadlines and
assertions. Both public-byte relay processes were retired with listener absence
verified. This establishes the documented qualification environment, not direct
upstream download reliability from every Linux network.

The first public-upgrade attempt stopped before prepare/apply because the baseline
Office conversion exceeded its effective default 60-second deadline under CPU
emulation. A mounted private deadline patch had been overwritten by later platform
defaults. Direct RPC reproduced the failure in about 63 seconds. The corrected
private fixture preserves product font directories and applies its 900-second
limit last; actual process arguments and effective configuration were checked,
and the same direct conversion passed in 129 seconds. The baseline is restored
to its default configuration before the upgrade transaction; default-to-default
and supplementary-to-supplementary generation comparisons are required. The
original failed attempt remains retained. A later attempt ran out of local disk
space while saving its pre-upgrade snapshot; it had not started the transaction.
Inactive downloadable caches were retired, the failure was retained, and preview
configuration writes were made idempotent for resumption. The resumed complete
upgrade and all post-upgrade checks passed. An administration screenshot captured
before React hydration was blank; it was retained, and a fresh login with explicit
page-readiness assertions produced the reviewed replacement screenshot.

Candidate code and clean-install/native/upgrade evidence passed independent
Standards and Spec review with no unresolved findings. Final documentation review
and checks are recorded in the accompanying acceptance JSON.
Private credentials, bootstrap links, hosts and runtime data are excluded. The
[historical local implementation record](https://github.com/dake6767/dsh-phalanx/blob/e0c46eab400c96a40db3f8a42e68d77016d50356/releases/acceptance/0.1.12.md) retains its original

### 修正与范围

首次源码 CI 暴露原生技能用例误列入受控浏览器组；该用例转入必需原生资格检查并通过，同时 CI 增加两项受控 MCP 管理/导入检查，未减少原生覆盖。

最初两次干净安装启动因私有脚本依赖解析缺失，在安装前停止。保留回执并连接未变更的依赖后，完整安装验收通过。首次临时公共上游未通过正常 TLS 预检；停止该端点后，新端点在产品检查前通过证书验证。

博查固定 uv 包的默认公开下载过慢；单命令 TUNA 索引返回的 wheel 与官方 PyPI 大小及 SHA256 一致。源码归档校验、冻结锁、Python 版本及真实提供方地址未变。首次组合复验中博查准备与连接通过，但完整 Chrome 下载超时；后续私有输入使用官方 `--no-shell`，保留固定 MCP 真正使用的完整 Chrome for Testing，仅省去不用的 headless-shell 包。运行参数、准备期限与功能断言保持。随后复验又遇固定 CPython 制品下载超时，单独延长读取等待未解决。固定 CPython 与 Chrome 官方制品经摘要校验后通过临时公开字节转发；Python 最小准备探针已通过。真实提供方请求仍直连原提供方。全新完整组合在原产品期限与原断言下通过。两项公开字节转发服务均已停止并确认监听消失；该结果不代表所有 Linux 网络均可稳定直连上游下载。

公开升级首轮在 prepare/apply 前停止：CPU 模拟环境中的基线 Office 转换超过实际默认的 60 秒期限。私有超时补丁被后续平台默认配置覆盖；直接 RPC 约 63 秒复现失败。修正后的私有夹具保留产品字体目录，将 900 秒期限最后应用，并核对实际进程参数及生效配置；同一直接转换用时 129 秒通过。升级事务前恢复基线默认配置，分别要求默认与默认、补充与补充的代际比较。原失败保留。后续一次尝试在保存升级前快照时遇本机磁盘写满，尚未开始事务；清理未使用的可重下缓存、保留失败，并把预览配置写入改为幂等后接续。完整升级接续及后置检查均已通过。首次管理页截图在 React 就绪前采集而为空白；原图保留，另以新登录及明确页面就绪断言取得并审阅补充截图。

候选代码及干净安装、原生资格、升级证据均通过 Standards / Spec 独立审查，无未解决发现。最终文档审查与检查记录在配套验收 JSON 中。公开记录不包含凭据、bootstrap 链接、私有主机或运行数据。[历史本地实施记录](https://github.com/dake6767/dsh-phalanx/blob/e0c46eab400c96a40db3f8a42e68d77016d50356/releases/acceptance/0.1.12.md)保留原始范围，不能替代本次托管候选资格检查。

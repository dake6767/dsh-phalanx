# 0.1.12 local implementation acceptance

## English

This record covers a local installation candidate, not a published release or a
hosted CI candidate. Platform source: `d032cd96915c97cb4acf28e507158a658929f01d`.
Platform archive SHA256: `91aa7dd65e09d22bce8adf3fab4ea41d09660d27c0ae50e8b05da0d709679bf3`.
All 6,040 installed files and symbolic links match the archive.

The DSH revision remains `d743267388641bc76f17c45ce8b4c231aed1d32c`.
The validation image ID is
`sha256:fef4f0422339bd727a654f0154418b05b6f4563b43c97db8e436112a3fb2f65b`.
It was built from the accepted frozen image using the repository's toolchain
extension for pinned pip and browser system libraries. This does not establish a
complete base-image rebuild or a published OCI image.

### Completed checks

- Context7, GitHub, Amap, Bocha and Playwright returned real tool results in one
  installed candidate for two members in separate groups. Group grants, member
  selection, required services, disabling, revocation and removal passed without
  member instance restarts. GitHub tool restrictions blocked disabled tools.
- Platform credentials were absent from member environments, MCP entries,
  profiles, process arguments and environments, and retained test evidence.
  Shared carriers used isolated sessions and read-only prepared dependencies;
  member commands used their own workspace.
- The published 0.1.11 platform preserved plugin, skill and skill-pack grants and
  selections, and member files when upgraded to this candidate. Real DSH then
  called an MCP tool. Separate old/new DSH image tests regenerated MCP entries
  and prepared both shared and member dependencies for the changed identity.
- Browser checks covered the four app-center tabs, local tab failures, account
  and recovery actions, English/Chinese copy, mobile navigation and the existing
  member/plugin administration framework. Development-entry checks passed on a
  separately built copy of the frozen DSH revision.
- Quick checks passed 364 cases in 127 files. Typecheck, lint, both builds and
  documentation checks passed. Independent standards and specification reviews
  covered the implementation and subsequent test corrections.

### Scope and corrections

The broad Linux run and focused corrected runs, together with four Mac development
checks, passed 79 distinct cases in 63 files. This combines installed/rootless
acceptance, controlled browser regressions and development tests; it is not a claim
that every case exercised an installed container. The initial broad invocation
failed; each applicable failure was corrected or supplied its required test input
and then passed a focused rerun. Six historical or unrelated cases remained
skipped, and the two deployment-qualification files below were excluded.

Initial attempts exposed missing test inputs and stale test assumptions: a
container-name filter missed named members; installed-client fault injection
used the source string; quoted Git filenames omitted two Chinese fixtures; an
old AnySearch sample was incompatible; and upgrade readiness needed to include
real package preparation. Focused corrected runs passed without relaxing product
checks. Temporary HTTPS and public upstream fixtures were supplied for their
respective regressions.

A pristine Ubuntu installation/reboot, long-running deployment preview, hosted
release CI and formal image promotion belong to release qualification. Historical
upgrade paths and unrelated paid model-provider cases are not newly certified by
this record. No private host identity, credential or runtime data is included.

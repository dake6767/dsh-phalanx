## Changes

The release aligns platform administration and entry pages with the existing Phalanx visual system, uses HeroUI controls and account drawers, and retains explicit saves, permissions and draft protection. The native DSH account entry follows sidebar styling; its menu, feedback and accessible names follow DSH Chinese/English selection and upstream language fallback. Platform pages remain English. The account schema, stable spaces, pinned DSH runtime and two-phase update protocol remain unchanged.

## Evidence boundaries and corrections

The original Linux run had 17 passing cases and two failures. The environment-reset test targeted HeroUI's visually hidden checkbox input; it now clicks the visible label, verifies checked/button states and toggles using Space, with the original full recovery assertions preserved. The plugin test encountered a native mirror-registry connection error. A focused retry through the official npm registry installed the same pinned plugin version and passed model-selection, restart and actual network-call checks. Both initial failures and successful focused results are retained by digest. Neither correction changed candidate product bytes.

The pristine-guest installation was accepted in segments: its first browser harness reached the 30-minute limit while TCG was still loading the image. The initial timeout was retained. Two continuation-harness attempts failed before bootstrap: one changed a deployment fixture URL, and one read an overwritten process log. Their failures are retained; the completed continuation uses the original deployment configuration. After the original installer and image-loading processes exited, a continuation rechecked guest, disk, boot, installer and candidate identities and completed the original native-use, repeat/corrupt-package and reboot assertions without resetting data or bootstrap credentials. A stale read-only SSH boot-ID probe was reconnected during reboot; the original polling and reboot assertions remained intact. The configuration checksum baseline was taken after installation completed. The accepted aggregate references both the initial failure and the continuation result; this is not a claim that the first invocation passed within 30 minutes.

The three source-mode supplements are the original shared-model administration case and two storage guards; they are not represented as installed-package tests. Models used controlled Messages/SSE fixtures, not live commercial model credentials or a model-quality benchmark. Plugin installation used the actual public package registry.

Clean-install candidate assets were delivered as a checksum-verified bundle. For the old formal baseline, the guest installer consumed a process-scoped replay of verbatim recorded public GitHub release/tag metadata and original verified 0.1.3 assets. This is not claimed as a live internet installer-download test. Formal publication separately verifies anonymous public downloads and image access. This release reran actual CLI upgrade and affected Web control behavior; it does not claim a new exhaustive Linux Web-executor fault-injection matrix. Existing production deployments were not updated.

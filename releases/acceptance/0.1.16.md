specified no-key migration case; arm64 passed five files / six smoke cases.
Both jobs passed two-identity isolation and cleanup. arm64 remains a development

retained accounts, model settings and member files, and returned a new DSH reply
in the Mac browser. The complete T3 inventory passed 65 regular cases plus the

clock, browser and CI-diagnostic failures remain separate from the passing runs.

The installed candidate's native T4 inventory covers eight files / ten cases:
real shared models, member contributions, GitHub MCP, private Amap and Bocha
samples, the combined MCP samples, installed MCP market/update behavior, and

the platform. One unchanged single-file rerun passed the complete contribution
flow in 285.79 seconds. Acceptance combines that rerun with the nine original
passes and retains the failure. For these native checks, candidate and test harness are the same commit;
there are no modified product bytes or weakened assertions. Known credential
scans reported no exposure. This is an accumulated pass, not a claim that the
first complete batch passed.

### Installation and download sources

Upgrade from formal **0.1.15** passed through the actual installer using verified
candidate bytes: insufficient-capacity rejection retained the old service, then
the successful upgrade retained accounts, MCP grants/selections and member
files. Actual DSH and MCP calls passed before and after upgrade. Earlier-version
binary upgrades are outside this release's acceptance inventory.

Trusted nonstandard HTTPS passed with certificate validation enabled. The first
clean-install attempt exhausted its 30-minute whole-test budget while the offline
image import was still progressing. Harness commit
`a9289b43725d1eb582dcc3a5990bc83f5c81be48` raised the total budget to 90 minutes.
The first fresh-VM rerun completed installation and service activation in 2580.4
seconds, then timed out waiting 30 seconds for the expected unconfigured-model
error. Native DSH was retrying the expected 503; focused reproductions showed the
correct error after 32.9 and 28.1 seconds. Harness commit
`58e670431e9ab59fde778e2d4542d47db464f761` allowed 90 seconds for that same visible
error assertion. Both failures are retained; no product bytes changed.

A second fresh-VM rerun passed the complete clean Ubuntu installation case,
including prerequisites, separate member-data storage, repeat installation,
corrupt-package rejection and recovery, native DSH streaming and terminal behavior,
preserved member files, and an actual VM reboot with a changed boot ID. The
controlled upstream in this installer test is distinct from the real-provider
checks above.

A separate mainland-China online VM installed formal **0.1.15** and upgraded to
the same candidate run. Both operations used the shared mainland preset for assets and execution: the
GitHub asset prefix remained ghfast and the GHCR mirror remained Nanjing University. Original platform hashes and image digests
were verified; no ad hoc mirror was introduced. Installer invocation counts and
transport diagnostics are retained with the evidence. The first baseline attempt
received HTTP 403 from the configured GitHub API proxy after its public quota
was exhausted, before deployment began. The unchanged command and preset were
retried after the reported reset; the failed attempt remains recorded. The first
candidate upgrade then failed before deployment because the configured API proxy
blocked the compare path. With explicit maintainer approval, only the GitHub API
category used direct api.github.com access for candidate verification; the asset
and image sources stayed unchanged. The same VM and formal baseline were resumed,
and this failure is also retained. Functional offline upgrade
and online delivery are separately recorded.

Download-source acceptance also covers administrator preset changes, actual
runtime dependency preparation, explicit command/environment precedence,
restricted plugin prechecks, and rejection of tampered/truncated proxy responses.
Candidate delivery was verified anonymously against the original manifest.
Standards and Spec review report no remaining findings. Formal promotion must
reuse these accepted package bytes and image digest without rebuilding.
